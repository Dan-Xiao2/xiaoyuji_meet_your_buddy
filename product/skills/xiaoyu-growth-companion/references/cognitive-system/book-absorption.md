# 书籍吸收流程：从内容摘要到判断系统

## 这套流程解决什么

书籍不是一个可以直接复制进 Prompt 的“知识包”。一本书可能同时包含事实、研究、经验、价值判断、故事、修辞和作者个人偏见。小宇记要吸收的是可验证的判断材料，不是保留作者的整套语气。

目标产物不是“这本书讲了什么”，而是：

- 哪些观点可以成为候选原则？
- 这些原则适用于哪个年龄、场景和家庭？
- 它们与现有原则有什么冲突？
- 什么情况下不应该使用？
- 能否转成不诊断、不排名、低屏幕、可观察的产品行为？

## 六个阶段

### 1. 来源与许可登记

记录作者、书名、出版机构、版次、年份、文件来源、是否为扫描版、授权状态和复核日期。版权不明时只能内部研究，不能把全文或扫描页纳入商业知识库。

### 2. 原子观点提取

每条只写一个观点，并区分：

- 作者明确主张的内容。
- 作者引用的研究或专业共识。
- 作者的实践建议。
- 我们从上下文推测出的内容。

每条观点都要保留页码或章节位置，供内部复核；仓库只保存原创摘要，不复制段落。

### 3. 证据与反例审查

将观点与 `source-registry.json` 中的中国官方指南、专业共识或开放教材交叉核对。若来源过时、适用人群不同、文化语境不匹配或有明显争议，保留争议并降低状态，不得因为多本书重复就自动升格。

### 4. 映射到统一系统

每条通过初审的观点只能进入以下一个或多个位置：

- `principles.json`：稳定的产品判断底座。
- `heuristics.json`：遇到什么情况采取什么动作。
- `tensions.json`：它与另一项重要目标如何冲突。
- `anti-patterns.json`：什么时候不能这么做。
- `knowledge-cards.json`：已经可以给特定年龄家庭使用的低风险内容卡。

不能直接把整本书做成一个独立 Skill。书籍是来源，统一判断系统才是产品资产。

### 5. 案例验证

至少设计三类案例：

1. 书中明确讨论过的已知案例：检查是否忠实。
2. 书中没有直接讨论的新案例：检查是否能由原则推导，而不是编造作者观点。
3. 与另一来源冲突的案例：检查系统是否保留分歧，并按宪法处理优先级。

每个案例都要检查年龄适配、证据来源、家长可执行性、隐私、医学边界和是否把孩子标签化。

### 6. 接受、暂缓或拒绝

- `accepted`：来源、年龄、授权用途和产品行为均已核对，可进入知识卡或原则库。
- `internal_only`：有研究价值，但授权、时效或证据还不足，只供内部研究理解。
- `needs_review`：需要专业人员、版权确认或更多上下文。
- `rejected`：与产品宪法、儿童安全或证据标准冲突。

## 书籍评审最小模板

复制 `templates/book-review.md`，每本书先写一页评审，不要一开始就写大量摘要。评审必须包含“可以吸收什么”和“明确不吸收什么”。

## 运行时原则

当前阶段这些资料只支持内容研发和人工评审，不直接改变 Tutor。只有通过来源登记、冲突审查、案例评测和专业复核的原则，才允许进入运行时生成链路。
