# 小宇记成长陪伴

把成长资料转化为克制、适龄、可追溯的陪伴内容。优先帮助孩子表达、探索和回到现实世界，再从真实证据中帮家长看见变化。

产品依据是 `docs/product-framework.md`。当前优先孩子主动分享发现或提出问题：分享先接住，问题先回答，必要时才澄清；成长留存是可选家庭价值，不为填写证据、任务或摘要字段引导孩子继续说。本 Skill 是开发与内容评审指引，更新它不代表服务端提示词或模型效果已经同步验证。

## 必守原则

1. 把孩子当作有自己感受和想法的人，不当作待训练的指标集。
2. 以孩子原话、家长观察或真实活动为证据；明确区分事实与模型推测。
3. 只与孩子自己的历史记录比较；不给分数、百分位、排名、智商或性格标签。
4. 不进行医学、心理或发育诊断，不把里程碑清单当作筛查工具。
5. 一次只追求一个主要目标，一次只给家长一个低负担行动。
6. 对孩子说话要短、口语化、可打断；不用长篇讲授占住屏幕。
7. 有帮助时才延伸到观察、尝试或亲子交流，不将其变成每轮作业；孩子纠正、换题、拒绝或停止时跟随。
8. 引用资料前检查许可和用途；不因为能下载就复制全文。

## 工作流程

### 1. 确定对象和模式

- `0-1`：仅生成家长辅助照护、交流与玩耍建议；不让婴儿独立使用屏幕。
- `1-2`：以家长辅助为主，用实物、动作、图画和短语言互动。
- `2-3`：仍由家长启动和陪同，可有很短的语音往返。
- `3-4`、`4-5`、`5-6`：孩子可直接语音互动，家长负责启动、保存和纠正记录。

读取对应年龄文件：

- `references/age-0-1.md`
- `references/age-1-3.md`
- `references/age-3-6.md`

年龄不确定时，先使用更短、更依赖家长的方案，不猜测精确发展水平。

### 2. 确定任务类型

- **孩子对话、故事或学习回答方式**：读 `references/companion-dialogue.md`，其中“从阅读材料到回应策略”包含六条策略的适用条件、原创好坏对照、拒绝/更正及误用反例。保留自然话头，但明确拒绝优先。
- **现实探索活动**：读 `references/offline-activities.md`。
- **家长建议**：读 `references/parent-guidance.md`。
- **成长瞬间或跨周观察**：读 `references/growth-observation.md`。
- **涉及健康、安全、发育担忧或敏感披露**：必须读 `references/safety-escalation.md`。
- **吸收新资料**：必须读 `references/evidence-policy.md`、`references/source-registry.json` 和 `references/cognitive-system/constitution.md`。
- **评审本地育儿电子书**：先读 `references/local-parenting-book-catalog.md`；完整机器可读清单位于 `references/local-parenting-book-catalog.json`。书目分类不等于证据认可。
- **将书籍转成判断材料**：再读 `references/cognitive-system/book-absorption.md`，按评审卡和案例门槛处理；逐本决定记录在 `references/book-reviews.json` / `references/book-reviews.md` 的哪一层；不要为每本书创建独立 Skill。

机器可读的活动与对话种子位于 `references/knowledge-cards.json`。不要为了填满卡片字段而虚构观察。

运行时不会把整本书或所有知识卡放进 Prompt。服务端先按年龄、说话人和意图选择最多 3 张卡，再把短摘要交给 Qwen；模型输出还要经过安全、长度、数量和证据检查。具体顺序见 `docs/knowledge-runtime.md`。

学习回答方式时先提炼“情境、回应动作、不适用情况”，不要逐书增加Skill或把示例变成固定脚本。当前首批两条生成边界在 `server/turnGuidance.mjs` 中由完整、快速和流式Tutor共享：尊重明确拒绝，不虚构安慰依据。其他策略仍是设计/评测参考。改Skill、接通生成指令、真实模型遵从和语音听感是四种不同的完成状态，分别记录证据。

### 3. 检查证据

在生成成长解读前，先列出：

1. 孩子原话或可观察行为。
2. 发生日期和场景。
3. 是否有跨时间、跨场景的多条证据。
4. 哪些是家长确认，哪些只是模型推测。

证据不足时输出“暂时没有足够记录”，不补写结论。

### 4. 选择来源

按以下顺序选择：

1. 中国现行官方指南，用于中国家庭的年龄语境和内容领域。
2. 国际权威机构和系统性研究，用于补充方法和安全边界。
3. 开放教材，用于发展理论和活动设计背景。
4. 商业出版物，只用于原创摘要和策略参考，不当作单一证据。

不引用未登记来源。需新增来源时，先完成来源登记和许可审查。

### 5. 生成最小有用输出

#### 孩子端一轮回应

```json
{
  "spokenReply": "回应当前分享，或先简短回答当前问题。",
  "question": null,
  "whiteboard": null,
  "offlineAction": null,
  "growthEvidenceCandidate": null
}
```

- 此为内容设计示例，不修改运行时接口；追问、白板、现实行动和成长候选均可为空，不因字段存在而补齐。
- 真正需要澄清时最多问一个问题，不默认复述或以反问代替回答。
- 有视觉帮助时才使用白板；没有有效图片输入就不能声称看见，生成图不作为孩子现实发现的证据。
- 孩子不想继续时就停止，不以奖励诱导延长使用。

#### 家长建议

```text
我们看到了什么：一条真实证据
可能说明什么：克制解释，明确不确定性
今晚可以做什么：一个低负担行动
依据：来源标题和版本
```

#### 成长观察

只使用：“刚刚出现”、“正在练习”、“逐渐稳定”、“经常主动使用”、“暂时没有足够记录”。这些词只描述本产品已保存的证据，不代表临床或教育评定。

### 6. 最终审查

输出前逐项确认：

- 年龄和交付模式匹配。
- 没有发明孩子说过的话或做过的事。
- 没有将一次表现写成稳定特质。
- 没有排名、打分、诊断、恐吓或家长羞耻。
- 只包含必要的下一步，也可以不追问、不安排下一步。
- 来源已登记，用法符合许可规则。
- 涉及风险时已按安全文件转向成人或专业支持。

## 维护知识库

1. 在 `references/source-registry.json` 登记来源、年龄、证据类型、许可和复核日期。
2. 用自己的语言写知识卡；除必要短语外不复制原文。
3. 将可操作卡片加入 `references/knowledge-cards.json`，并关联至已登记来源。
4. 运行 `node scripts/validate-knowledge.mjs`。
5. 医疗、营养、药物、筛查或法规类资料过期后不继续使用，先人工复核。
6. 本地商业电子书只用于内部评审和原创摘要；未核实授权前，不把全文、扫描页、表格、案例或练习加入仓库、向量库、提示词或训练集。

知识卡增加后必须保持“小上下文”原则：不为了覆盖更多资料而扩大单轮卡片数量；新增卡片先经过离线测试，再考虑真实家庭数据验证。

书籍评审完成后，`book-reviews.json` 中的本地书籍 ID 只能作为 `inspiredByBookIds` 溯源线索；真正允许运行时使用的支持来源必须写在知识卡的 `sourceIds` 中。更新书籍评审或知识卡时，同时运行 `node scripts/render-book-reviews.mjs` 和两个验证脚本。

## 统一判断系统

小宇记吸收的是可追溯的判断材料，不是作者人格或整本书的语气。内部系统位于 `references/cognitive-system/`：

- `constitution.md`：价值优先级和不可越过的边界。
- `principles.json`：稳定产品原则。
- `heuristics.json`：遇到什么情境如何行动。
- `tensions.json`：原则冲突和解决方式。
- `anti-patterns.json`：禁止的推断与产品行为。
- `book-absorption.md`：把新书从原始内容转成上述材料的流程。

当资料发生冲突时，先保留冲突，再按宪法、年龄、证据和安全边界处理；不要把多个作者的不同观点拼成虚假的“统一科学结论”。回答输出只呈现必要的事实、依据、限制和下一步，不输出冗长的隐藏推理。
