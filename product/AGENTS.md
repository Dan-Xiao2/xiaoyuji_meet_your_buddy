# 小宇记仓库开发约定

## 当前开发方式（用户最新确认）

当前由用户本人独立开发和维护小宇记。产品、前端、后端、语音、内容、测试与发布由同一人按优先级推进；不假设额外开发者、固定全职投入或多人并行产能。外部体验反馈或专业复核按需要另行安排，不等于已有固定成员。

后续计划按工作步骤和实际可投入时间估算；每次只推进一个核心改动，再验证。旧协作启动资料已归档，不作为当前人数、职责或工期依据。

在修改产品、内容、设计、数据或交互前，必须先阅读：

- `docs/product-framework.md`
- `docs/development-log.md`
- `DESIGN.md`（涉及 UI 时先读；新方向先确认样板，已确认方案使用共享视觉变量与组件同步更新桌面和手机；不将样板模拟逻辑带入正式页面）
- `docs/architecture/README.md`（涉及组件职责、接口、数据流、存储或外部服务时）
- `docs/ui-motion-guidelines.md`（涉及页面、组件、交互或动效时）
- `skills/xiaoyu-growth-companion/SKILL.md`（涉及0-6岁内容、活动、故事、家长建议或成长观察时）
- `skills/xiaoyu-growth-companion/references/source-registry.json`（新增或引用育儿资料时）

这是当前产品决策的最高依据。新增功能必须能说明真实使用场景、对孩子或家长的具体价值、所依据的证据，以及对屏幕时间和儿童数据的影响。

## 不可默认改变的原则

- 产品叫“小宇记”，AI 陪伴角色叫“小宇”。
- 产品的 North Star Goal 是孩子愿意带着发现和问题来，小宇能够接住并跟随。成长时间线是随后积累的家庭价值，不为记录、报告或课程诱导孩子持续聊天。
- 优先入口：“我想让你看看我今天发现的东西”“我有个问题”。分享先接住，问题先回答；允许不追问，孩子纠正或换题时跟随，不默认要求选颜色、画图或完成现实任务。
- 单张照片分享与理解是待验证方向，不等于现有附件或图片生成能力；接收、发送和保存权限及事实性验收完成前，不声称小宇已经看见，不上传真实家庭照片用于开发验证。
- 产品整体服务0-6岁家庭；当前先打通3-6岁孩子直接语音，0-3岁采用家长辅助模式；幼儿园主要是测试和触达渠道。
- 核心场景是家庭在共享手机或旧平板上一次设置、自由开始 voice-first 对话，不设陪伴倒计时，也不要求每轮按住说话。
- 孩子端保持一个主要语音入口和按需出现的视觉白板。
- 产品不替代父母、老师或同伴，不做刷题、诊断、监控或情感依赖设计。
- 合适时把好奇心带回观察、尝试或亲子交流，不把现实活动作为每次必做的作业。
- Student Memory 必须区分原始证据与模型推测，不给孩子贴固定标签。
- 不只维护会被覆盖的“当前画像”；必须保留带日期的 Growth Moments，才能展示孩子如何变化。
- 家长端只呈现理解孩子和继续陪伴所需的信息，不混入开发策略或内部工具。
- 没有真实数据时隐藏摘要、任务和趋势模块；动效只用于操作反馈和状态变化。
- 儿童数据默认最少收集，并提供家长查看、下载和删除能力。
- 成长资料必须登记来源、版权用途和复核日期；公开可下载不等于可以复制进商业知识库。

若实现需求与这些原则冲突，不要直接绕开原则开发。先在 `docs/product-framework.md` 中记录新的用户证据和决策变化。

每次完成一个功能、改变功能范围或确认新的技术缺口后，必须同步更新 `docs/development-log.md` 的状态表和日期记录。

## 架构同步规则

- 当前运行架构的可编辑真相源是 `docs/architecture/xiaoyuji-runtime.architecture.json`，展示文件是同目录下生成的 HTML。
- 新增、删除或改变核心组件职责、API、数据存储、外部模型、信任边界时，必须同步更新架构源并重新生成 HTML。
- 普通文案、颜色、间距或组件内部重构没有改变系统关系时，不更新架构图。
- 图中只能出现当前真实接通的能力。未来能力写入开发日记，或另建 future-state 图，不能伪装成当前运行架构。
- 更新后至少运行 `npm run check:architecture` 和 `npm run architecture:build`；完整规则见 `docs/architecture/README.md`。
