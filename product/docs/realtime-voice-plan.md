# 真实语音功能升级计划

> 2026-11-12：语音现状与路线以 [voice-status.md](voice-status.md) 为准。本文是 2026-09 到 10 月的升级计划，保留为历史；其中“回答时停止收音、不是全双工”“以 LiveKit 设计为准”等说法已经过时：网页语音已有开口打断（页面回声消除、先确认再打断），LiveKit 实验暂停，另有戴耳机可用的通话模式实验。说话人识别的设想仍以本文为参考。

> 2026-10-27 状态校正：当前代码已存在单句实时 ASR（AudioWorklet → `/api/asr/realtime` → Qwen），并保留录音上传回退；仍在回答时停止收音，不是全双工。下文早期“下一项仍是流式 ASR”等段落保留为历史，当前代码审查与拟议迁移以 [LiveKit 接入设计](livekit-hybrid-architecture.md) 为准。该设计尚未实施。

当前 MVP 已在保留浏览器降级能力的同时接通 Qwen 云端语音：浏览器录音上传至后端，`qwen3-asr-flash` 转成文字，Tutor 生成回答后由 `qwen-audio-3.0-tts-flash` 合成语音。API key 只在本地服务端 `.env` 中，浏览器不会取得密钥。

这条半双工链路已升级为“一次开始 → 本地静音断句 → 上传语音 → 文本理解 → 合成播报 → 自动重新倾听”。它适合当前单人 MVP 和小规模试用，并已完成合成中文音频的真实往返测试；目标手机、旧平板、真实儿童发音、噪声、播放权限、回声和打断仍需真机验证。正式产品若需要更低延迟和真正双工的自然打断，再升级为后端签发临时会话的实时语音架构。

当前已经可以建立 1 个主孩子档案，并另外登记最多 6 位家长或照护者。家庭可以在聊天前或聊天中手动选择“现在说话的人”。系统会记住上一次选择，但**目前不会自动根据音色判断身份**。这是诚实的产品降级，不把普通语音转文字包装成说话人识别。

## 为什么不能只靠浏览器内置语音

### 2026-09-06：先消除当前链路中的串行等待

- 已实现 Qwen SSE 到 PCM 的流式播报，使用现有密钥、模型与音色；不需要额外购买一套服务。
- 短回答开始播报前先保存本轮记录；白板补全不再阻止自动续听。
- 新轮次和结束会话取消旧请求、待播声音及续听计时器；迟到补全不能覆盖下一轮或复活已删除的记录。
- 增加断句、ASR、短回答、首音频和实际播放开始的分阶段耗时，测试结果见 `docs/voice-latency-check.md`。
- **下一项工程任务仍是流式 ASR**：录音时逐块发送，中间转写只作状态反馈，最终转写确认后再触发一次 Tutor；保留批量 ASR 回退。先验证首音延迟分布、断句完整性和错误触发，再考虑自动语音打断。
- 不能仅把 `QWEN_ASR_STREAMING_MODEL` 填入环境变量就声称已经接通。当前仍是录完再上传，仍需真实设备、网络、儿童发音和回声验证。

### 浏览器能力限制

- 不同浏览器支持不稳定。
- 很难做到自然打断、低延迟连续对话。
- 不能稳定和白板工具、Student Memory、离屏任务联动。
- 无法作为正式儿童产品的长期语音基础。

## 推荐架构

```text
Browser
  ↓ 请求临时语音会话
Backend /api/realtime-session
  ↓ 使用服务端 API key 创建 ephemeral session
Realtime Voice Agent
  ↓ 工具调用
Tutor Engine
  ├── Student Memory
  ├── Interaction Planner
  ├── Whiteboard Commands
  └── Offline Activity Assignment
```

## 家庭说话人识别

语音转文字和说话人识别是两件不同的事。正式能力需要单独的说话人注册与验证服务：

```text
家庭成员明确同意并录入短语音
  ↓
后端提取说话人向量，不在前端保存模型密钥
  ↓
新语音与家庭内最多 7 个向量进行比对（1 个孩子 + 6 位家长/照护者）
  ↓
高置信度：标记成员身份
中间置信度：请用户确认
低置信度：显示“无法确认”，不猜测
  ↓
ASR 转写 + 已确认身份一起进入家庭对话记录
```

实现边界：

- 自动识别只做家庭内说话人归属，不作为身份认证或安全验证。
- 每位成员单独同意录入，支持重新录入、关闭识别和彻底删除声音向量。
- 尽量不长期保存原始音频；保留期限、供应商处理方式和删除结果必须在上线前明确。
- 家长说的话保存为“家人观察”，不能自动变成孩子兴趣、能力、情绪或发展结论。
- 儿童与家庭语音属于高敏感设计范围，正式试点前需要独立完成隐私、供应商和合规审查。

## 前端要保留的接口

`src/services/voiceService.js` 现在是一个替换点。后续可以保持同样的外层方法：

- `listen({ onStart, onResult, onError, onEnd })`
- `speak(text)`
- `stop()`

换成 Realtime 后，`onResult` 不只是听写文本，还可以接：

- 中间语音转写
- AI 语音回复状态
- 白板工具调用
- 安全拦截提示

## 后端临时会话接口

未来新增：

```text
POST /api/realtime-session
```

返回：

```json
{
  "client_secret": "ephemeral_token",
  "expires_at": "2026-08-21T12:00:00Z",
  "student_id": "local-demo-student"
}
```

原则：

- 真实 API key 只放服务端。
- 浏览器只拿短期临时 token。
- 每次会话绑定匿名 `student_id` 和家庭内 `speaker_id`，不要直接传孩子真实姓名、照片、学校班级。

## MVP 升级顺序

1. 先用现有 Qwen 半双工链路完成目标手机、旧平板和真实儿童语音测试，记录 ASR、Tutor、TTS 各段延迟和失败原因。
2. 校准专有词、儿童发音和噪声场景，完成移动端播放、打断和浏览器回退。
3. 保留手动说话人确认，继续打磨家庭对话、一次设置、成长证据和回看流程。
4. 当连续对话的真实需求与成本得到验证后，再增加 `/api/realtime-session`，先在本地测试。
5. 让 Realtime Agent 先调用 `whiteboard_command`，再接 Student Memory 写入。
6. 最后做最多 7 位可说话成员的说话人注册、置信度确认和删除机制，不把它混进第一版 ASR。
7. 小范围家庭和幼儿园测试前，增加家长同意、数据匿名化和删除机制。
