# 原生 App：难点和步骤（2026-11-13）

> 2026-11-13 第 0 步已做：用户在同一台 iPhone（iOS 27）上用豆包或 ChatGPT 的 App 开语音通话，外放，边听边插话约一分钟，**没有炸音**。说明 iOS 原生音频在外放下可以做到不炸音、能插话，问题出在 Safari/WebKit，原生这条路走得通。这只说明原生能做到，我们自己写的版本能不能做到同样效果，要靠第 1 步验证。
>
> 2026-11-13 用户决定开始第 1 步技术验证：测试 App 在 [`native/ios/`](../native/ios/README.md)，比较三种方式（A 通话级回声消除、B 回声消除 + 普通模式、C 不消除），带小宇的测试录音、插话判断和安静时误触发计数，不连网、不录音。用户装好 Xcode 27.2 后，模拟器版和真机版（未签名）都编译通过，没有错误和警告，录音和麦克风说明已打包。已装到用户 iPhone（iOS 27.0.1）。第一版 A 没有声音：打开回声消除后 iOS 立刻重新配置音频并停掉引擎，已改为自动重启引擎、播放前确认引擎在运行。A（通话级回声消除）iPhone 外放真机：不炸音；插话 10/10 被听到；安静 64 秒误触发 0 次；安静时麦克风最高 -56 dB、插话时 -18 dB（门槛 -38 dB），系统音量 45%。还要确认：不贴着手机能否听清、音量调到八成左右是否仍不炸；B、C 未测。
>
> 用户 2026-11-12 决定暂不做原生 App。这份文档回答“如果要做，难在哪里、怎么做”，供之后决定时用。背景和手机外放的调研见 [rtc-phone-speaker-research.md](rtc-phone-speaker-research.md)，语音现状见 [voice-status.md](voice-status.md)。

## 一、要换的是声音这一块

- 只把现在的网页装进 App 壳（WKWebView）不够：壳里的网页用的还是同一套 WebKit 录音和放音，iOS 27 外放炸音的问题照样在（WebKit 326286、167788）。
- 所以 App 里**录音、播放、判断打断**要换成 iOS 自己的接口：`AVAudioSession` 设为边录边放、语音通话模式，`AVAudioEngine` 打开系统回声消除，也就是 FaceTime 这类通话用的处理。小宇的声音要从同一个音频引擎播放，系统才知道该消掉什么。
- 其他部分不用换：界面（网页）、成长记录、小宇记的服务器、阿里云百炼的识别、回答和合成。
- 不建议改用阿里云的原生通话 SDK：那会把通话模式的服务、费用和规则一起带回来，又变成两条路。

## 二、主要困难

| 困难 | 说明 |
|---|---|
| 还没验证能解决 | 原生的系统回声消除在 iOS 27 外放下表现怎样没测过；打开后外放音量可能比普通播放小一些。这是最大的不确定 |
| 开发环境 | 这台 Mac 只有命令行工具，没有 Xcode（2026-11-13 检查）。Xcode 从 App Store 下载，占几十 GB，要用户安装。炸音只能在真 iPhone 上验证，模拟器测不出来 |
| 代码量 | iOS 端用 Swift 写录音、播放和打断判断，再与现有网页代码对接（网页把音频交给原生，原生把识别和播放的状态告诉网页）。`voiceService.js` 有 900 多行，最好先按改进计划阶段 2 拆开。安卓要另写一份 |
| 苹果账号 | 苹果开发者计划每年 99 美元，各地价格不同（例如英国约 79 英镑、中国区 688 元），以苹果页面为准。只装到自己手机，用免费 Apple ID 也行，但每 7 天要重新安装。发给试点家庭要付费账号走 TestFlight，外部测试要先过苹果的测试版审核，一般一两天 |
| 安卓分发 | 国内没有 Google Play。试点阶段直接发安装包最简单。上国内应用商店一般要软件著作权、App 备案，不少商店只收公司账号，还有隐私合规检测 |
| 中国区上架 | 要 App 备案；据公开报道，生成式 AI 应用在苹果中国区会被要求提供相关备案或登记信息；放进儿童类别还有家长门控、不能用第三方统计和广告等规定。这些更适合用公司主体办（[deployment-cn.md](deployment-cn.md) 第七节） |
| 服务器照样要部署 | API 密钥不能放进 App，App 仍然连小宇记的服务器，境内部署和备案做不做 App 都要办 |
| 数据迁移 | 家庭在网页上的记录存在浏览器里，换到 App 要用现有的备份导出、再导入 |

## 三、步骤

| 步骤 | 内容 | 时间 | 谁做 |
|---|---|---|---|
| 0. 零成本验证 | 同一台 iPhone 打开豆包或 ChatGPT 的 App，开语音通话，外放，边听边插话一分钟。不炸音，说明原生这条路能走；也炸音，就不用做了 | 5 分钟 | 用户 |
| 1. 技术验证 | 最小的 iOS 测试 App：开着麦克风外放小宇的声音（`/api/speech/stream` 的 PCM），看炸不炸、音量够不够、能不能听到孩子插话、会不会被自己的声音打断。用免费 Apple ID 装到用户手机 | 装好 Xcode 后 1–2 天 | Claude 写代码；用户装 Xcode、真机测试 |
| 2. 原型 | 网页界面放进 App 壳，录音、播放和打断换成原生，接现有的实时识别和朗读接口；网页版保留 | 约 1–2 周 | Claude 为主；用户真机测试 |
| 3. 试点分发 | iPhone 走 TestFlight；安卓直接发安装包 | 几天 | 用户注册开发者账号 |
| 4. 上架 | 公司主体、App 备案、生成式 AI 登记、隐私合规、商店审核 | 数周 | 正式上线前 |

第 1 步通过的标准：iOS 27 外放、正常音量下聊 10 轮，没有炸音；小宇的声音不用贴着手机也听得清；孩子插话能被识别；小宇不会被自己的声音打断。

## 四、建议的顺序

1. ~~先做第 0 步（5 分钟）~~：已通过（2026-11-13）。
2. 做完网页“关掉开口打断、iPhone 外放聊 10 轮”的测试（[voice-status.md](voice-status.md) 第七节）。外放干净的话，试点不需要原生 App。
3. 试点数据里最大的意见如果是“打断不灵、不够即时”，并且第 0 步通过，再开始第 1 步。

这样原生 App 不挡在试点前面，也符合“一次只推进一个核心改动”。

## 五、和其他方向的关系

- **端到端实时语音模型**（如百炼 Qwen-Omni-Realtime）：是替换网页语音背后引擎的候选。它在 iPhone 网页外放下同样受 WebKit 问题限制；放进原生 App 才能真正做到边说边听。
- **通话模式**：开关先保留（2026-11-13 用户决定），原生 App 不走它。
