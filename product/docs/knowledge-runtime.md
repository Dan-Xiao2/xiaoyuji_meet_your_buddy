# 知识卡运行时规则

这份说明记录“小宇记”如何把已审核的知识卡用于一次 Tutor 请求。它不是把育儿书籍全文交给模型，也不是让模型自由选择一套教育流派。

## 一次请求的顺序

```text
用户输入 + 年龄 + 当前说话人
        ↓
意图识别：安全 / 入园 / 情绪修复 / 同伴 / 绘画 / 阅读 / 探索 / 语言 / 普通
        ↓
按年龄和交付方式过滤
        ↓
按优先级选最多 3 张知识卡
        ↓
把卡片的短摘要注入 Qwen system prompt
        ↓
Qwen 返回 Tutor JSON
        ↓
输出检查：长度、数量、来源证据、安全边界
        ↓
通过后才合并到白板、离屏活动和 Student Memory
```

## 当前实现

回应方式另有两条共享生成边界：尊重孩子明确拒绝，不虚构安慰依据。定义在 `server/turnGuidance.mjs`，由 `server/qwenTutor.mjs` 的完整、快速和流式快速生成入口共同注入；不扩大知识卡数量，不发送书籍示例全文。其他回应策略只供Skill设计/评测参考。指令接入不等于模型遵从，且本地安全/控制/白板提前返回路径不经过模型；见 [实施与验证边界](changes/2026-11-01-dialogue-response-patterns.md)。

- 选择器：`server/knowledgeCardSelector.mjs`
- Qwen 接入：`server/qwenTutor.mjs`
- 自动测试：`server/smoke-test.mjs`
- 可运行知识卡：`skills/xiaoyu-growth-companion/references/knowledge-cards.json`
- 来源登记：`skills/xiaoyu-growth-companion/references/source-registry.json`

每次最多选择 3 张卡，且只把以下字段送入 Prompt：卡片标题、目的、最多 3 条观察信号、最多 3 条陪伴动作、一个简短的线下活动和来源 ID。原始书籍文件、扫描页和整段正文不会进入运行时。

## 稳定性规则

1. **年龄先于内容偏好**：卡片必须匹配当前年龄段。年龄不确定时使用默认的 4-5 岁短回应，并在正式 0-3 岁模式完成前保持家长辅助边界。
2. **身份影响交付方式**：孩子可以收到孩子语音、共享设备或家长辅助卡；家长输入只使用家长辅助或共享设备卡。
3. **少量上下文**：单轮最多 3 张卡，避免随着书库扩大而把 Prompt 变成不可控的资料堆。
4. **安全优先**：安全输入由本地安全规则处理，不让 Qwen 替换安全转向。
5. **模型只能建议**：模型不能自行声明“使用了某张卡”，也不能自行写入来源。服务端把选中的卡片 ID记录在 `llmStatus`，而不是信任模型回传的 ID。
6. **证据先于结论**：孩子的 `growthEvidence.sourceQuote` 必须来自本轮输入；家长输入的 `shouldSave` 必须为 `false`。
7. **失败可回退**：超时、网络错误、JSON 解析错误、输出检查失败，全部回到本地 Tutor 结果，不写入不可靠的模型内容。

## 输出检查

`validateTutorOutput` 当前会拒绝：

- 空回答或过长回答。
- 白板超过 5 个项目、线下任务超过 4 步。
- 家长输入试图创建孩子成长证据。
- 诊断、排名、智商、百分位、发育迟缓等结论性话术。
- 模型编造、且无法在本轮输入中找到的孩子原话。

通过检查后，`mergeLlmTurn` 仍会再次做白板、故事、活动、年龄长度和成长证据归一化。检查不是“相信模型”，而是把模型限制在产品已经定义的边界内。

## 如何扩充知识库

2026-11-01 新增的六份儿童沟通漫画只进入内部书目评审及原创评测题，未进入运行时知识卡。逐本取舍、候选策略、现有选择器缺口和最小A/B流程见 [沟通材料使用方案](changes/2026-11-01-child-communication-materials.md)。新增评测题不等于新规则已生效或模型已训练。

先增加来源登记，再新增一张小卡，不要直接把一本书变成一组 Prompt。每张卡都需要：

- 适用年龄和交付方式。
- 一个明确目的和可观察信号。
- 最多一个低负担现实活动。
- `sourceIds` 中的可运行来源。
- 书籍只能作为 `inspiredByBookIds` 的内部线索。
- 明确的 `avoid`，防止把一次观察升级成标签或诊断。

新增卡片后运行：

```bash
npm run check
```

在有真实家庭数据前，不要因为卡片数量增加就扩大每轮 Prompt。先观察：回答是否更贴题、家长是否更容易接住、孩子是否更愿意离屏探索，以及是否出现新的误导或重复话术。
