# 白板开源吸收记录

更新：2026-09-09。

## 本轮实际接入

| 来源 | 吸收的部分 | 没有做的事情 |
|---|---|---|
| [Microsoft Fluent Emoji](https://github.com/microsoft/fluentui-emoji) | MIT Flat 小兔、汽车矢量；本地可审计、指定部件改色，保留许可证与固定版本 | 没有批量导入所有图案，不宣称任意图都可画 |
| [tldraw Agent template](https://github.com/tldraw/tldraw/tree/main/templates/agent) | 借鉴精简画布上下文、结构化操作、执行后检查的设计；本项目自行实现 catalog 和对象保护校验 | 没有复制代码、安装 tldraw SDK 或把模板许可当成 SDK 商业许可；未实现截图反馈给模型 |
| [Konva](https://github.com/konvajs/konva) | 保留已经接入的积木画布 | 没有强行迁移已工作的 SVG 插画、门窗编辑和逐句播放 |

Motion Canvas、ELK 和图片生成 API 本轮未安装或接入。当前一个人维护的首要任务是同一对象可以连续修改，避免新增第二套编辑状态。

## 运行边界

`drawingCatalog.js` 统一名称、别名、层级、默认色、素材与可改部件，供本地意图、场景校验、渲染和模型能力表使用。模型只能返回现有操作，不能提交 SVG、图片URL或可执行代码。

`drawingConstraints.js` 识别明确的整对象保护短句，例如“兔子不要变”“别动兔子”“保持兔子不变”。检查提交结果及每个播放帧；包括 move 交换位置带来的间接变化。未识别的保护对象要求澄清。这是有限中文语法，不是通用语义验证，也不是永久锁定对象。

本地待选目标会保留同一操作的保护ID，回答“好的、左边的”等不会丢掉它。模型跨轮规划尚不提供永久锁定；新的复杂请求应明确保留对象，后续需统一跨轮约束协议。

规划上下文只发送当前对象、ID、revision、nextId、能力清单和保护ID；不额外发送成长记录、整份历史或画布截图。复杂位置请求仍通过现有 Qwen 文本规划器；只说“旁边”且两侧都空时需确认方向。

## 体验验收

1. “画一只小兔”：初始空白后显示小兔。
2. “在小兔右边加一辆汽车”：同一张画布上增加汽车，不重新生成兔子。
3. “汽车变蓝，兔子不要变”：只改车身，保留车窗和轮胎，兔子节点与属性不变。
4. “撤销”：恢复上一步完整画面；刷新与成长快照保留这些对象。

新增单元测试 `tests/drawing-assets.test.mjs`；浏览器 `tests/drawing-assets-browser.mjs` 在390、768、1440px运行真实页面、检查图形像素、边界、对象身份和备份快照。浏览器规划响应为模拟数据，因此不代表真实模型成功率。

2026-09-09另做两条匿名真实Qwen规划抽样，右侧增加汽车和保留小兔改车色均通过；详情和token用量在开发日记。这不是足够规模的语义成功率评测。

## 仍然缺少

- 更丰富的审核素材与统一画风；当前新增图形是矢量素材，不是实时自由手绘。
- 超过3个地面对象的布局、任意部件和开放式插画生成。
- 独立自然语言评测、真实儿童表达与手机麦克风测试。
- 图片生成后的编辑一致性、生成成本/等待时间和内容审核。

这些保持待做，不通过新增几种对象就把“通用白板”标记完成。
