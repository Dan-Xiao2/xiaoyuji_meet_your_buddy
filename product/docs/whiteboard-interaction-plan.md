# 白板交互：先验证一个完整场景

更新：2026-09-07

## 最新里程碑

本轮按用户确认的方向，完成对象画布底座及Qwen受约束操作规划接入；当前范围、五段分镜、真实接口抽样和后续阶段见 [共创里程碑](whiteboard-cocreate-milestone.md)。以下旧试点记录保留作为历史依据；简笔画已升级为v2对象、关系、局部修改和撤销。仍不是自由插画生成或完整教学白板。

## 用户实测后的修正

用户报告明确“画一个房子”被拒绝、太阳话题跳到积木。本轮补上真实简笔画入口，不再仅用积木例子代表绘画能力：

- `illustrationPlan.js` 识别明确画图请求，支持房子、太阳、树、云朵；同一幅画添加对象、屋顶改为预设颜色。未知对象说明暂时画不准确，不替换成积木；“我喜欢画画”是分享，不自动开画。
- `illustrationScene.js` 使用已审核的对象路径和 Rough.js 呈现；不执行模型生成代码，不是开放式图像生成或通用绘画工具。
- 家长也可发出画图命令，保存时仍归为家人输入，不能增加孩子掌握度。
- 快速回答和完整回答共用能力说明和话题原则。删除给模型的 `localFallbackPlan` 示范，移除“一句话搭积木”标题；旧练习只接收明确答案，不占用新问题。
- 明确科学词“太阳几岁”“太阳加热空气”不会仅因“几/加”被分类成减法。
- 新增画图浏览器回归：画房子 → 加太阳 → 屋顶改色 → 问太阳 → 不支持对象。两种屏幕已检查截图；备份保留subjects和颜色。
- 真实Qwen匿名测试又发现错误的太阳机制和不合适观察引导，增加有限事实种子及已知错误回退，见 `science-factual-seeds.md`。复测3轮快速对话和1次完整回答未跳到积木，其中1条触发事实回退；不表示任意科普已获保障。

## 本轮要解决什么

旧白板把不同主题套进固定图形，短口语回答和完整白板还来自两次独立生成。增加手绘线条不能解决内容不相关、讲解和画面不同步的问题。

本轮先做“分积木”的有边界试点，不声称已经达到通用 Studdy 式讲解水平。孩子看到可点数、会移动、追问后仍然是原来那几块的对象；不增加学习评分。

## 当前可试

1. 开始对话，说“我有五块积木，给爸爸两块”。
2. 第一段话呈现五块；第二段语音实际开始播放时，把两块移过去。
3. 接着说“再给爸爸一块”“拿回一块”或“三块”。
4. 可以点积木计数，点回放图标再看一次。点数、回放本身不生成成长证据。
5. 换话题取消旧动作。没有准确图示的回答保留语音，不再自动展示月亮或通用关系图。

约束：1–10块、一个接收方、明确数量、有限中文句式；不支持多人物连续分配、任意物品替换或开放式积木建造。越界先澄清，不能悄悄改成五块。

## 实现职责

- `src/whiteboard/visualPlan.js`：纯函数生成数量、稳定场景ID、版本及讲解步骤；限制数量、说话人和支持的追问；过滤不合适的旧白板。
- `src/services/tutorEngine.js`：安全和家长观察分流后调用场景计划。命中试点不发两次独立文本请求；其他对话继续原来的 Qwen 流程。
- `src/app.js`：同一组步骤交给语音和画板。语音开始回调触发对应移动；新输入、结束、恢复备份使旧播放失效。
- `src/ui/blockScene.js`：Konva 对象层，稳定 block ID、位置补间、点数、尺寸适配与 reduced-motion。
- `src/ui/whiteboard.js`：保留同一画板实例、更新版本、回放和清理。普通界面刷新不会重新生成积木。
- `src/data/localStudentDb.js`：保存经过验证的场景快照，备份恢复保留同一份结构。
- `src/whiteboard/whiteboardCommands.js`：命令描述用于检查；运行时仍由白板分发器直接消费 board/scene，不把描述层冒充通用执行引擎。

当前同步是“分段语音开始 → 该段动作开始”，不是词级对齐。两段TTS仍顺序请求，真实网络下可能有段间停顿；自动测试的模拟音频不能证明真实语音延迟达标。小宇讲话时仍不是全双工监听。

## 开源取舍

| 项目 | 本轮使用 | 不直接吸收的部分 |
|---|---|---|
| [Konva](https://github.com/konvajs/konva) | MIT，实际安装，用对象节点、点击事件、补间和销毁生命周期 | 不让模型输出任意可执行代码 |
| [Lucide](https://github.com/lucide-icons/lucide) | ISC，实际安装，回放按钮使用标准图标 | 不给孩子堆绘图工具栏 |
| [Excalidraw](https://github.com/excalidraw/excalidraw) | 参考克制的手绘视觉与画布交互；未安装 | 不搬入完整编辑器或协作系统 |
| [Motion Canvas](https://github.com/motion-canvas/motion-canvas) | 参考讲解与画面共用时间顺序；未安装 | 没有接入其视频生成流程 |
| [tldraw agent](https://github.com/tldraw/tldraw/tree/main/templates/agent) | 参考模型动作与画布执行分离；未安装 | 商业使用许可需单独核对，不能当作无条件免费SDK |

依赖保留包内许可证。这里不是声称吸收了整个仓库，也不复制未知授权的素材。

## 验证与下一步

- 单元测试：`npm run check:whiteboard`，验证数量边界、话题切换、安全优先、家长身份、场景及本地备份。
- 浏览器测试：`tests/whiteboard-browser.mjs`，隔离数据与模拟音频，检查390/768/1440px、跨帧移动、语音步骤、对象身份、点数、取消、无关内容过滤和快照。
- 原有语音和档案测试继续运行，避免为了白板破坏自动续听、保存、家长整理和恢复。
- 下一步先补段间音频预取与真实延迟测量，再考虑第二种“颜色/形状分类”场景；之后才是故事分镜、因果示意与受验证的模型场景规划。
- 每种新场景须有支持范围、失败时空白或澄清策略、内容样例及反例、桌面/手机检查。不要先扩大可画类型，再补语义正确性。
- 家庭验证后再判断价值：孩子是否理解图示、是否能自然追问、是否愿意回到真实积木活动；不把停留更久作为成功指标。
