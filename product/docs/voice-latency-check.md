# 语音延迟验证与下一步

更新：2026-10-04。这里只保存工程结果，不保存家庭录音、原话或密钥。

## 2026-10-04 实时识别接入

- 默认在Qwen配置可用时启用实时识别，`ASR_REALTIME=false` 可关闭。模型用独立变量 `QWEN_ASR_REALTIME_MODEL`，默认 `qwen3-asr-flash-realtime`；旧 `QWEN_ASR_STREAMING_MODEL` 属于不同协议，不作为本通道配置。真实 `.env` 未修改。
- 沿用 `QWEN_BASE_URL` 的地区/工作空间主机及服务端Key，WebSocket路径 `/api-ws/v1/realtime`。现有账号已成功收到 `session.updated`；没有让用户申请新Key。
- 浏览器AudioWorklet由16kHz AudioContext采集单声道PCM16，小段约100ms。检测到发言前只保留最近800ms本机内存，不建立云连接；检测到发言后经同源 `/api/asr/realtime` 边说边上传。约1050ms停顿判断及15秒单轮上限沿用原值。
- 服务端手动commit，最终转写只提交一次；中间文字和供应商情绪字段不进入Tutor、页面原话或成长记录。网络断开、无最终结果或采集不支持时，用本轮完整MediaRecorder录音裁剪转WAV，经原接口回退。计时可见回退原因；回退可能产生两次识别费用。
- 取消、换轮、切页通过现有stopListening关闭采集和连接，迟到结果被轮次ID丢弃。密钥只在服务器；WebSocket校验Origin、限制4个活动连接、消息大小、总音频量和等待时间。这仍是本地MVP，不是生产账号鉴权。
- 新计时：`asr-realtime-connect`、`asr-realtime-final`、`asr-realtime-fallback`。final测量录音结束后剩余等待，不是识别总耗时；音频时长仅本页内存用于调试，原始录音不落盘。

真实接口抽样：`scripts/probe-realtime-asr.mjs --live` 用一句固定合成中文、同一份3.144秒PCM对比实时与批量，两条结果去标点后均匹配。实时连接1020ms，发送结束后等待1567ms；批量上传后等待2099ms。各一次、非随机顺序、不含采集、静音断句、LLM和TTS播放，不代表稳定节省532ms或儿童识别表现。探针仅在显式 `--live` 时调用三次付费API，不读取麦克风或家庭档案，不写录音。

自动验证：`check:voice` 20项通过，完整 `npm run check` 通过；新增浏览器测试用真实AudioWorklet/MediaRecorder及合成音频，模拟WebSocket返回，覆盖390/1440px边说边上传、重复最终结果、断线完整回退、录音中取消、等待结果时取消、连接就绪较晚和无发言不上传（两种尺寸各6场景）。原有 `voice-browser.mjs` 及完整录音裁剪 `voice-capture-browser.mjs` 回归通过。架构重新生成并通过9项产物检查。真实儿童/噪声和目标设备延迟仍待测。后续段落为历史记录，旧“实时ASR未完成”描述以本节为准。

协议依据：[阿里云实时识别](https://help.aliyun.com/en/model-studio/real-time-speech-recognition-user-guide)、[客户端事件](https://help.aliyun.com/en/model-studio/qwen-asr-realtime-client-events)、[服务端事件](https://help.aliyun.com/en/model-studio/qwen-asr-realtime-server-events)。

## 先确认实际输入设备

2026-10-02：设备选择与本机试听隔离浏览器回归通过（390/1440px）；15项语音单测、原语音回归和正式页面回归通过。用户真实收音、ASR准确率和端到端延迟仍待验证。

家庭设置 → 麦克风：手动点击“允许并读取麦克风”，选定设备后“录一小段”。测试最多8秒，试听原始录音；不调用ASR/Tutor/TTS，不上传或写入成长档案。清除、收起、切页、后台和关闭会释放音轨与试听URL。音量条仅显示输入强弱，不代表语音准确率。

设备选择独立保存在本浏览器 `xiaoyuji-microphone-device-v1`，不导出到家庭JSON；清空本机数据同时删除该偏好。正式聊天录音复用同一约束，指定设备不可用则提示重选而不是退到默认设备。设置内“上次聊天输入”来自最近录音音轨的标签，仅本次页面有效，不是系统设置推断。原生浏览器听写无法保证使用指定设备，不冒充已固定输入。

验证顺序：试听是否清晰/完整 → 同句真实ASR是否准确 → 分阶段耗时是否过长。本机试听未通过时不先更换云端模型；试听通过也不能直接证明ASR正确。本轮没有真实儿童或真实麦克风测试。

实现参考：[MDN enumerateDevices](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/enumerateDevices)、[MDN deviceId](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/deviceId)。未授权时设备名称可能不可见；打开设置不会自动请求许可。

## 2026-09-30 用户迟缓反馈与录音修复

从用户正在使用的页面只读取得分阶段控制台耗时，没有提取原话、录音或凭据。几轮普通模型回答的 `response-start` 为4189/4569/4547/4217ms，另有约1050-1067ms断句等待。对应ASR约1599-2234ms，短答约1565-1961ms，TTS首音约688-908ms。它们来自有限现场日志，不是总体P50/P95或物理扬声器测量。当前整句ASR、短答生成、TTS首段串联，约五秒等待不是单一供应商阶段造成。

已修复：

- 原先只留文件头和最近几个MediaRecorder分块，会丢弃中间容器片段。现在完整解码，再从检测到有声之前800ms开始裁剪，输出单声道PCM WAV；不能用拼接编码碎片代替音频裁剪。
- 录音内容只在内存转换，不保存到磁盘或成长档案。未检测到发言不上传；长等待前缀在本机裁掉。裁剪依赖声音检测，噪声误触发仍可能带入无关声音，不能承诺完全消除。
- 音量分析使用浮点采样与更长分析窗，避免字节量化和视觉平滑干扰声音检测。没有未经真实儿童验证就降低阈值或缩短停顿。
- 音频上下文暂停时主动恢复，恢复失败/超时或录音器启动失败时退出并提示重试，不默默等待90秒。转换失败不把破损录音提交上游。
- 新增 `audio-prepare` 耗时，独立记录完整解码与裁剪开销。WAV通常比压缩录音大，上传与解码成本需真机测量，不声称此改动必然降低端到端延迟。

验证：`check:voice`12项通过；`tests/voice-capture-browser.mjs` 使用真实Chrome MediaRecorder和Web Audio合成音频，不打开真实麦克风、不调用云API。2秒静音后播放短音，最终WAV约2.45秒，有声约从0.68秒开始；验证容器可解码及前缀裁剪，而非中文或儿童识别准确率。390/1440px原有语音浏览器回归及 `npm run check` 通过。

当前不能确认用户是否选错麦克风，已询问测试设备及是否触发iPhone连续互通；不自动切换系统输入设备，不读取家庭录音。

下一里程碑：实时ASR，不再等录完整句才上传。先核对当前账号/地区支持的实时接口、价格与音频协议，再接入一条可取消的实时识别会话；中间转写只显示状态，最终文本才进入安全检查、Tutor与成长记录，断线不得重复提交。保留当前路径作为显式回退，标明回退耗时。用固定成人自愿测试语料对比完整漏字/错字、P50/P95和每轮成本，验证后再测试儿童声音。播报时插话及真正双工另行实现，不与实时ASR混为已完成能力。

### 历史说明

下面是9月6日的实现与观测。旧的“仅保留容器头”方案已被上面的完整解码裁剪替代；当时8项单元测试现已扩展为12项。

## 本轮真实服务探测

使用现有 Qwen 配置和合成的匿名中文文本/音频。以下各为单次样本，不是 P50/P95，不是同一句话的严格 A/B，也不是孩子说完到实际听见的端到端结果：

| 阶段 | 观测 |
|---|---|
| 短口语回答 | 2170ms，真实模型被调用，48 字 |
| 旧整段 TTS 请求、取得并下载 MP3 | 2700ms |
| 将合成音频送入当前批量 ASR | 5189ms，转写成功 |
| 新流式 TTS，HTTP 请求到首段 PCM | 1396ms；服务端首段计时 1335ms |
| 新流式 TTS，整条网络流完成 | 1903ms，126546 字节 PCM |

结论：流式出口真实可用，但不能把 1396ms 宣称为完整对话延迟。ASR、模型生成、音频设备启动和断句等待仍会叠加。不同样本的音频长度不同，不能据此宣称某个百分比加速。

## 已修改的等待与保护

1. TTS 不再等待整段合成及二次 MP3 下载：服务器转发 24kHz 单声道 PCM，浏览器首段到达就排入播放时间线。
2. 播报结束后约 200ms 自动续听，不再等待白板/结构化证据的完整请求。
3. 短回答生成后立即保存本轮记录，迟到补全更新同一 ID。新轮次会取消旧请求；已经保存的原话不会因为取消补全而丢失。
4. 请求取消、结束聊天、切换页面停止待播声音；部分播出后断流不从头重播。首段前失败保留整段 MP3、浏览器合成两级回退。
5. ASR 开始时关闭录音资源并切换“正在想”，不继续显示正在听。保留最初录音容器头，避免等待后裁掉头部的 WebM 无法解码。
6. 完整模型超时覆盖响应体，不只是等响应头；取消文本请求传到上游。取消不保证供应商已经发生的计费能撤销。
7. 快速播报路径也经过现有本地安全规则，不绕过已有保护。这不是完整的儿童内容安全认证。

本地静音阈值仍为约 1050ms，没有为了速度贸然切短孩子停顿。录音仍每 250ms 收集分块、说完才上传；保留容器头不等于已经实现流式 ASR 或无损去静音。

- `npm run check:voice`：8 项单元/接口边界测试，覆盖 SSE 网络切分、PCM 样本和队列、停止、坏流、片段补全、防覆盖、安全以及模型响应体超时/取消。

- `tests/archive-browser.mjs`：原有成长整理、导出、恢复回归。
- `npm run check`：知识库、架构、档案、语音和旧业务冒烟检查。

运行浏览器测试需安装 Playwright 与 Chrome。可用 `PLAYWRIGHT_MODULE` 指向已安装的模块，`CHROME_PATH` 指向 Chrome，`TEST_URL` 指向测试服务；默认测试服务为 4174。

## 后续如何定位

开发控制台 `window.xiaoyuVoiceTimings?.()` 返回本页最近 80 个阶段耗时，不持久保存，不含原话。常用阶段：

- `endpoint`：最后有声之后的断句等待。
- `asr`：浏览器发起转写到拿到文字；`serverLatencyMs` 是服务端测量，二者不可互换。
- `quick-reply`：短回答请求耗时。
- `tts-first-audio`：播报请求到首个音频节点计划播放，包含已知设备基础延迟的估计，不是物理扬声器采样测量。
- `response-start`：录音停止开始处理到首音播放回调，不含前面的静音断句等待。
- `tts-stream-fallback`：流式首段前失败，已切换整段路径。
