出现以下任一变化时更新架构：

- 新增、删除或拆分核心运行组件。
- API 路径、同步/异步关系或主要请求顺序改变。
- 数据从本地浏览器迁移到新存储，或新增跨设备同步。
- 更换或增加文本、ASR、TTS 等外部模型服务。
- 儿童数据的信任边界、权限或处理位置改变。
- 本地 fallback、知识系统或结构化输出的职责改变。

只有文案、配色、间距、图标或组件内部实现改变时，不更新架构图。

## 更新步骤

1. 先确认代码中的真实关系，不从计划或产品愿景推断已实现能力。
2. 修改 `xiaoyuji-runtime.architecture.json`，尽量保持已有节点 ID 稳定。
3. 运行架构校验：

   ```bash
   npm run check:architecture
   ```

4. 只有校验通过后才生成展示文件：

   ```bash
   npm run architecture:build
   ```

5. 打开 HTML 检查标签、线路、缩放、聚焦视图和桌面可读性。
6. 在 `docs/development-log.md` 记录本次架构变化和仍未实现的部分。
7. 最后运行项目总检查：

   ```bash
   npm run check
   ```

可选的自动浏览器检查：

```bash
npm run architecture:visual-check
```

如果自动浏览器无法启动，应如实记录环境失败，并继续人工查看正式 HTML；不能把“生成校验通过”描述成“视觉检查通过”。

## 维护原则

- 当前图只画当前系统；未来系统另建 `future` 图，不混在一张图中。
- 主链路优先，保持 8-12 个核心组件；支持细节写入卡片，不用更多箭头堆满画布。
- 原始数据、模型推测、家长可见总结必须保持边界清楚。
- 每次修改后保留 Archify 的校验结果；失败时按诊断修复，不通过删除重要标签来获得通过。
- 生成的 HTML 与 JSON 一起提交，方便非技术合作方直接打开查看。
