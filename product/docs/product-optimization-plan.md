## 1. 判断与修正

之前方案的方向成立：明确状态所有权、减少入口文件协调职责、分离证据与推测、保留本地优先及分层验收。但执行顺序需要调整。

- 拆文件不是完成标准。控制器若持有旧整份状态再回写，只是把覆盖风险搬到另一个文件。
- 不先创建十种实体和多层通用框架。用现有家庭对话、成长回看、作品和备份流程决定最小边界。
- 不要求所有功能都具有同一套状态。语音、绘图、档案保存分别定义合法转换与终止条件。
- TypeScript 可提供静态检查，但不能验证模型 JSON、授权或数据库数据；先建立运行时契约。
- 预先模块化已知变化点：供应商、存储、对话与画面发布。多孩子、商城、硬件、临床产品暂不实现。
- 产品“完成”需要行为证据。代码质量、真实模型表现、设备表现、家庭价值分别验收。

## 3. 产品交付范围

下一里程碑：一个 3-6 岁孩子及最多六位照护者，在共享手机或旧平板上从孩子的发现或问题开始可靠交流；纠正和换题有效、视觉按需；有合适内容时家长能够选择保存、纠正、回看并恢复。技术验收可强制测试保存，真实使用不要求每轮形成记录。

固定三条验收旅程：

1. 家庭首次同意与设置 → 选择麦克风/说话人 → 分享或提问 → 纠正/换题 → 结束 → 重新打开，无重复记录、无自动恢复收音。自动夹具使用多轮，真实孩子不规定轮数。
2. 孩子提出画图要求 → 画图期间继续聊天 → 修改图画 → 撤销或失败保留 → 家长选择保存作品。
3. 家长查看成长片段 → 纠正转写/归属或删除 → 摘要同步更新 → 导出 → 在全新浏览器上下文恢复。

价值观察沿用产品框架：先看孩子主动发起、回应相关、纠正有效和自然再使用；再看家长接受与可选的保存、回看和后续交流。聊天时长、记录条数、图画数量不能单独证明价值。

## 4. 最小责任边界

| 责任 | 唯一写入者/入口 | 不允许的行为 |
|---|---|---|
| 家庭资料与说话人 | 家庭操作命令 | 对话模型或后台补全修改当前身份 |
| 本轮原话与已播回复 | 带 sessionId / turnId 的回合提交 | 用返回的 messages 数组替换整段历史 |
| 当前白板与作品版本 | 绘图提交，携带 jobId / baseRevision | 成长提取覆盖画面；过期编辑覆盖新版 |
| 成长证据与家长修订 | 成长存储操作，携带源 turnId 与修订版本 | 模型撤销家长修改、复活删除记录 |
| 摘要与兴趣变化 | 从可用证据派生 | 把 AI 回答、故障重试或空数据当成长事实 |
| 录音、播放、页面状态 | 内存中的交互控制 | 持久化后自动恢复麦克风或待执行任务 |
| 本地长期资料 | 档案 repository 的事务 | 页面直接写多个存储键并宣称保存完成 |

先为已有 turn、session、moment 和画面版本补齐稳定 ID、schemaVersion、来源与修订约束。Family 账号权限表随联网试用需求再引入。SafetyDecision 保留最小临时状态，不建立长期敏感原文档案；模型调用日志使用短期无内容元数据。

### OPT-03 建立可解释的语音链路与运行时契约

- 状态：待实施；依赖：OPT-01/02；负责人：工程，真实设备由用户验证。
- 先抽样记录“用户最后一个声音 → 结束检测 → 转写确认 → 首段文本 → 首个可听音频”；用共同 requestId 关联服务端和浏览器耗时。
- 提取 voiceInteractionController，管理倾听、处理、播报、暂停、失败和结束；设备采集与供应商适配保留独立模块。
- 不依靠页面多处布尔值决定录音。结束、拒绝权限、断线、锁屏/后台、播放失败统一释放资源并产生可解释终态。
- API 请求与结果增加版本、长度边界、有限错误码和运行时校验；失败不可伪装成空成功。首声指标以实际播放事件为准。
- 日志只存阶段、耗时、状态、模型配置和费用可用性；不含录音、原话、图像字节、设备标识或家庭姓名。提供本机诊断导出。
- 验收：合成输入连续 20 轮无重复发送、残留录音或旧播报；取消后不续听；每个失败可定位阶段；至少一个目标真机随后完成三轮验证。
- 初始体验目标（待基线校准）：普通短答从停止说话到首声 P50 ≤ 2.5 秒、P95 ≤ 5 秒，注明设备/网络/样本数与失败率。至少 30 次虚构语音试次；它不证明儿童识别准确率。
- 回退：保留现有可控回退通道；语音与画图供应商变更分别开关、分别验收。

- 建立 20 个独立多轮场景，每场至少 3 轮，覆盖拒绝模板、转话题、澄清、家长/孩子归属、故事、事实问题、绘图及安全分流；保留未用于调试的留出集。
- 同步记录 git revision、提示词/知识卡版本、请求模型与供应商实际返回版本（未提供就明确标未知）、采样配置、样本分母和失败。
- 不让“创建失败所以没进入编辑”消失在分母；分别统计创建、条件编辑成功率和整段任务成功率；零样本为无法验收，不能通过。
- 成本覆盖 ASR、quick、后台提取、TTS、图像、审核和失败重试；缺失计费信息显式标部分估算，并设置批次预算上限。
- 知识卡验证包含有卡/无卡对照、冲突与过期资料处理、证据不足时不下结论；专家背书只能对应实际审核范围。
- 白板维持精确操作和开放图像两路；撤销/数量/已支持部件编辑用确定性验收，开放图像按语义匹配、未改部分保持和失败反馈人工复核。
- 验收：所有候选输出有独立人工结论；固定安全场景出现严重错误即阻断；普通多轮任务通过率目标 ≥ 90%、不必要重复追问 ≤ 10%（暂定内部回归门槛，不是市场宣称）。
- 回退：保留上一组模型/提示词/知识版本；质量不合格的画图能力可独立关闭，核心聊天和成长记录继续可用。

### OPT-06 用完整家庭流程检验产品价值

- 状态：待实施；依赖：所测路径对应的安全、状态、语音和数据门槛；负责人：工程准备，用户组织真实家庭。成人陪同的本地纯语音观察不必等待照片分享、全部存储迁移或任意绘图完成；未验收能力关闭。远程试用仍必须先满足 OPT-07。
- 第三节三条旅程用合成数据先自动验收，再在目标设备检查权限、字体、触控、等待与失败反馈；桌面和移动共用内容与状态。
- 专门验证一句真实内容如何变成值得保留的卡片：无数据、稀疏数据、记录纠正后、跨周数据各有清晰展示，不能编造趋势。
- 准备 5–8 个家庭、两周成人陪同试用，采用已有手工验收模板；不要求儿童按固定时长使用。
- 记录每个实际试用家庭是否完成第二次使用、主动保存/纠正、主动回看及后续交流；明确分母和退出原因，不用总对话量代替价值。
- 按最新主线区分孩子自主、家长提示与成人代操作发起；记录纠正是否被采纳、是否可自然结束和再次使用机会。孩子带自己的问题，不把工程测试的固定脚本交给孩子照读。
- 验收：每个家庭有技术问题与价值反馈分开的记录；形成继续、缩小或改变场景的书面决定。小样本只用于方向判断。
- 回退：若持续失败源于语音或白板，收窄可用范围；若家长不愿回看，优先改成长内容价值，而非再加入口。

### OPT-07 对外试用与运营准备

- 状态：待实施；依赖：OPT-01/02，必须在服务向远程家庭开放前完成；若 OPT-06 为远程试用，本项提前作为前置；负责人：工程，用户/管理员负责账户和部署授权，专业人员复核发布要求。
- 先支持“云端仅代理 API，本地保存档案”的最小模式。多人云同步只有明确需求后再增加。
- 服务端验证真实登录身份与家庭成员资格；不能信任前端 familyId，也不能以声纹或本地家长码替代授权。
- 所有付费接口有账户限额、速率限制、并发限制和请求成本上限；重复点击有操作 ID，不盲目重试付费图像创建。
- 如新增云档案，服务端按家庭范围查询；逐项覆盖读、改、删、导出和作品下载，家庭 A 不能通过换 ID 访问 B。
- 上线配置与测试配置隔离；健康检查、无内容告警、功能关闭、部署回退与一次恢复演练；写清本地数据和发送云端的音频/文本/图片边界。
- 记录同意、撤回、删除与保留规则；专业复核和当地发布要求由合适人员确认，不以本计划冒充合规结论。
- 验收：过期凭证、越权、超额度、重复请求、第三方中断均有可复现结果；远程开放前完成部署与权限检查。
- 商业验证先测家庭价值和包含图像失败/审核的单家庭成本；计费/会员功能有需求证据后再实现。
- 回退：关闭远程入口或受影响的付费能力，恢复已验证的部署；保留本地档案导出。涉及云数据格式变更时先确认数据兼容，不能只回滚代码。

## 6. 顺序、工作量和决策点

以下是任务拆分参考，单位为工程工作日，包含测试/文档，不是日历承诺；依赖权限、真实模型、设备与家庭的等待单独记录。

| 阶段 | 顺序 | 粗估投入 | 退出条件 |
|---|---|---|---|
| A 稳定基础 | OPT-01 + OPT-02 | 3–5 | 状态交错回归和干净环境发布检查通过 |
| B 主链路 | OPT-03 | 3–5 | 能测清每段延迟、取消/失败可靠 |
| C 可信成长 | OPT-04 | 4–7 | 记录修订、迁移、删除、恢复形成完整流程 |
| D 质量和体验 | OPT-05 + OPT-06 的自动/设备部分 | 3–5，加评测费用与人工时间 | 完整旅程质量有记录，可进入家庭试用 |
| E 对外准备 | OPT-07，在远程试用前 | 3–6，取决于部署选择 | 身份、额度、运营和恢复门槛通过 |

先完成 A 再重估后续投入。每次最多一个核心行为改动处于实施中；不要一次创建所有抽象层。学习活动逐步移为独立功能，依照调用关系和回归结果迁移，保留旧数据兼容。

当前优先执行：保留 OPT-01/02/04 的安全与可靠性开放项；下一批从 OPT-03/05 的“分享 / 提问 / 纠正 / 换题”样例和语音基线入手。原第一批覆盖修复与 Chromium 衔接已有本机证据，不重复标为尚未开始；远端 CI、跨标签页原子性等仍未完成。不等全部重构或照片分享完成才验证已有语音体验。

## 7. 一致执行机制

- 每个任务先复制 `templates/change-brief.md`，写一个能复现的用户场景及验收；小修复可在 PR 正文填写，不强制新增文件。
- 每个提交说明一个行为变化；先复现失败，最小修改后跑受影响测试，合入前跑 check:release。结构调整前先验证基线。
- PR 必查：状态写入者、信任边界、迟到结果、存储失败、迁移/删除和用户可见反馈；涉及项写证据，不涉及项标不适用。
- 在 CI 逐步加入针对已迁移模块的依赖边界和静态类型检查：UI 不直接调用供应商/写档案；供应商适配器不持有家庭状态。禁止靠目录名称假装隔离。
- 同步更新开发日记的任务编号/结果、变化涉及的契约和当前架构；历史记录不作为当前能力保证。文档“完成”必须链接验收证据。
- 复盘按里程碑或新故障触发，重新排优先级；不自动按固定日历扩功能，不以文件行数或测试数量衡量完成度。

## 8. 人工决策与工程可自主完成部分

- 工程可先完成：OPT-01/02、合成语音测试、诊断、存储迁移夹具、知识/模型评测脚本、正式页面交错回归和文档校正。
- 真实模型批次开始前明确样本、费用上限和停止条件；此前某次付费测试授权不自动转成无限预算。
- 用户后续提供：目标手机/平板验证、试用家庭组织、是否远程开放及账户/部署选择、评测费用预算。
- 专业合作者提供：育儿知识与高风险场景的审核范围、证据和复核日期；不能由工程测试替代。

人工项可后置；依赖它们的产品发布状态保持待验证，不阻塞独立工程任务。
