# 变更简报：语音实验的输入就绪证明、阶段计时与逐句流式回复

- 状态：自动验证通过（全部使用模拟的 ASR/LLM/TTS）；待真实服务对照与人工验收。
- 场景：成人在语音实验里说话，等到首音要 4–6 秒；曾有一次开头漏词；页面在输入未被证明到达识别器前就显示“在听”。
- 产品目标：孩子说完话能较快得到跟题的回应（North Star 的当下价值）；定位延迟/漏词时不靠猜。
- 范围（两件可独立理解的事）：
  1. 输入就绪证明与 ASR 计时：完成上一批已写好但未实现的 3 项失败测试（`tests/voice-lab.test.mjs` 第 11–13 项）。
  2. 回复流式化：模型按句输出，每句过检查后立即进入 TTS；TTS 按句请求并预取下一句；新增 LLM/TTS 阶段计时。
  后置：真实服务下的漏词根因、断句/VAD 参数调优、token 级别的细粒度流式、正式半双工页面的同类改造。
- 前置依赖：无新增依赖。
- 当前失败证据：`node --test tests/voice-lab.test.mjs` 11、12、13 项稳定失败（页面在输入未证明时显示 listening；就绪回调从未被调用）。延迟分解来自 `changes/2026-11-01-livekit-real-validation.md`。
- 数据所有权：不涉及家庭档案；实验仍完全不读写档案。
- 异步与错误：
  - ASR 握手前到达的音频按序、恰好一次地在确认后发出；握手前取消则丢弃；队列上限 10 秒音频。
  - 就绪 = 第一帧音频已 append 给识别器，而不是握手确认。重连会作废就绪，需代理重新应答 hello。
  - 流式回复：调用方取消 → 立即中止上游请求并以 AbortError 结束，不生成备用回答（与整段路径一致）。首句前失败 → 备用回答；已说出若干句后失败 → 在此结束。
  - TTS 任一句失败 → 流报错，并取消其余已预取的请求。
- 契约/迁移/删除/权限：`ready` 事件新增 `inputReady`（客户端要求其为 true 才显示 listening、才允许发文字）；新增 `timing` 事件（只含阶段名、毫秒、样本/字符计数，不含音频和文字）；页面对未知事件类型本就忽略。其余不适用。
- 验收：`npm run check:voice-lab`；全量 `node --test tests/*.test.mjs`；`node server/smoke-test.mjs`。
- 成本/数据流：每个回复仍是 1 次 LLM 请求（增加 `stream_options.include_usage` 以保留用量统计）。TTS 请求次数由“每回复 1 次”变为“每句 1 次”，总字符数不变；真实账单未测。
- 重要取舍：已放出的句子无法收回。后续句子未通过安全、已知事实或画图声明检查时，回复在该处截断，而不是整体替换；只有第一句失败才能整体替换为备用回答。
- 回退：设置 `VOICE_LAB_STREAM_REPLY=false` 回到整段回复；ASR 与客户端改动无开关，需回退文件（`voice-agent/` 目录尚未提交到 git，改动前备份在本次会话的工作目录，已不保证长期保留，建议先提交）。
- 文档：本简报与开发日记已更新。运行/实验架构图未改——没有新增组件、接口或存储，只是既有 LLM→TTS 链路内部由整段改为逐句。
- 结果证据：Linux 虚拟机内的独立副本（Node 22.23.4，依赖按 Linux 重装，不影响本机 node_modules）：`node --test tests/*.test.mjs` 416 项通过；`server/smoke-test.mjs` 通过；对三处关键逻辑做破坏性变异（关闭逐句安全检查、TTS 不按句切分、握手即报就绪），对应测试均变红，还原后 26 项（语音实验两文件）全绿。
