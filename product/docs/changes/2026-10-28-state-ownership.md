# 状态所有权第1步：收紧业务状态修改入口

日期：2026-10-28。范围：已提交状态的只读边界、家庭设置及会话生命周期的明确更新，以及现有对话/绘图路径与只读状态的兼容。当前记录不代表运行态、展示态和存档职责已全部拆开。

## 修改与目的

此前 appStore 返回可修改对象。主入口及订阅者可能在 commit 之前直接修改 store 的数据，导致旧快照一起变化。现在 store 在初始化、提交时复制可序列化业务数据，规范化后递归冻结；调用方输入仍可独立修改，不被意外冻结。getState、订阅通知和返回值均是只读快照。

新增 update(transform, event)，从 store 当前状态计算下一状态；返回原对象则不提交、不通知。更新函数若修改旧快照会抛错，store 不发布该变更。该入口是同步状态计算，不包含网络请求、DOM、存档或媒体操作。

applicationState 提供 updateProfileState、startSessionState、endSessionState：

- 资料更新同时同步主要孩子姓名和 Student Model 的资料字段，保留当前其他业务内容。
- 新会话通过现有规则创建会话并重置本次消息/白板；已在会话中重复开始不重新创建。
- 活跃会话结束时生成既有小结；重复结束不再修改状态。
- 家庭成员添加/移除、说话人切换继续复用现有 familyModel 纯函数，经 store.update 发布。

主入口承担表单读取、前置校验、操作顺序和副作用。家庭资料、家庭成员及会话生命周期不再原地修改共享对象。结束时仍先停止在途业务与媒体，再将清理后的状态和结束状态一起提交，保留第三批的取消语义。家长码清除经资料更新入口。

为在当前应用中启用只读边界，图片发布、绘图计数/状态、线下观察及重置的原地赋值也改为新对象提交；普通对话保留 conversationCommit 的受限接受及并发冲突保护。本轮未重写这些路径的业务语义。

## 当前修改权限

| 内容 | 当前入口 | 边界 |
|---|---|---|
| 已提交业务状态 | appStore.commit / update | 发布只读快照；调用方不能绕过提交修改已发布对象 |
| 家庭资料及衍生资料 | updateProfileState，经 update | 更新从当前状态出发；资料与主要孩子/模型资料同步 |
| 家庭成员及说话人 | familyModel 纯函数，经 update | 保留成员数量及主要孩子保护规则 |
| 会话开始/结束 | startSessionState / endSessionState，经 update | 原有权限/同意检查仍在主入口；重复生命周期操作不重建 |
| 普通对话 | applyConversationCommit 后 commit | 会话、消息、阶段及证据冲突保护继续有效 |
| 绘图、观察和恢复 | 原接收校验后，以新对象 commit | 已兼容只读状态，仍有较宽的旧提交接口 |

只读快照保证“已发布数据不可绕过提交原地修改”。它不会自动判断每个新对象的字段归属；commit(nextState) 兼容入口仍可提出较宽变更，领域授权并非全部由 store 强制检查。主入口中仍有局部候选状态变量；本步没有把它们全部迁入控制器，也没有宣称页面已成为纯装配层。

## 尚未解决与取舍

- llmStatus 仍混合模型诊断及多类任务进度；voiceUiState 与媒体状态的派生关系待下一步收敛。
- 未发布候选目前仍走既有对话结构，第三批停止清理规则保留；迁出正式历史属于运行态分离的后续工作。
- 保存、渲染仍在订阅端；成长存档及模型资料存在独立写入，保存失败与跨记录原子性尚未统一。
- 每次提交复制并冻结业务数据，换取明确的引用边界。当前自动回归不能证明大图片/长历史在旧手机上的性能，需独立测量后决定是否优化；不先增加结构共享框架。
- 同步 update 必须使用当前状态；异步网络、媒体和档案任务仍需各自的身份/代次校验。冻结不代替这些保护。
- 本轮探索回归的通过不能证明历史偶发超时根因已消失；LiveKit、实际已播内容及 iPhone 后台验证仍未完成。
