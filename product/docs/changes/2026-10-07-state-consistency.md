# OPT-01/02 第一批实施与验证记录

- 日期：2026-10-07。
- 状态：本批本地自动验证通过；OPT-01 和 OPT-02 总项仍为部分实现。
- 场景：家长在同一轮回复等待期间改昵称/切换家人，或者开放图片先完成，随后文本后台补全到达。
- 用户结果：新的家庭设置和白板不应被旧文本快照替换；后台补全不能把已说出口的内容改掉。
- 范围：普通对话 quick/enrichment 控制器、该路径的状态合并和浏览器启动。没有更换模型、修改密钥或启用新API。

## 失败证据与修复

1. 先加入6项控制器回归，旧代码5项失败：quick覆盖昵称、补全失败/不安全时覆盖昵称、安全短答回退覆盖昵称、后台覆盖家长观察。其中local分支最初断言不够强，后续改为断言用户指定的新昵称，不能把原来的通过视为该分支已安全。
2. 控制器接收getState，在每个异步返回后读取最新状态；回合取消之外检查session ID。应用接收返回后再检查当前回合。
3. 合并不再接受后台messages/board；家长可并发修改的memory/studentModel/growthEvidence在请求开始时记录序列化基线，发生变化则保留本地字段。结果返回冲突字段名，不包含儿童原文。当前应用尚未把该冲突列表接入诊断界面。
4. 添加2项会话替换测试；控制器共12项（本批新增8项），enrichment 2项、appStore 2项均通过。
5. 正式页面现有模拟测试在quick返回前提交新昵称、在enrichment返回前切换家人；390/1440px验证持久化后的值与消息数量，保留播报失败及重播检查。没有使用测试专用状态写入口。
6. 浏览器启动优先选择锁定Playwright包管理的Chromium；显式无效路径失败，不静默换浏览器。Mac已有浏览器只在托管Chromium缺失时作备用。

## 本机验证结果

- 环境：macOS，Node v22.22.3；本机现有依赖，不是从全新安装环境测试。
- `npm run check:release`：退出码0，包含单元/服务/smoke、5项浏览器路径选择测试、4条浏览器发布流程。通用流程覆盖390/768/1440px；本次新增同轮竞争流程覆盖390/1440px。
- 第一次受限环境 `check:browser` 在测试服务启动阶段退出1，尚未进入页面断言。授权环境重跑成功；不能将首次失败抹去，也不能据此声称远端环境正常。改为转发服务stderr，后续启动错误可见。
- 故障注入：`CHROME_PATH=/tmp/xiaoyuji-intentionally-missing-browser npm run check:browser` 退出1，明确报告浏览器路径无效。这只验证本地入口失败传播，不是远端required check验收。
- `npm run check:architecture`、`npm run architecture:build`：9项校验通过并生成HTML；未将其算作独立视觉验收。
- 所有页面数据为虚构数据，接口为模拟；没有真实/付费模型调用，没有采集或上传家庭录音。
