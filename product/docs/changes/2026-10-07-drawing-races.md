# OPT-01e 绘图异步状态保护

- 状态：本批本机自动验证通过；OPT-01总项仍部分实现，真实API与设备质量未验收。
- 场景：路由/规划等待期间家长保存资料、图片先完成、撤销或结束后旧请求返回。
- 范围：只修绘图结果的合并、基图校验与失败保留，不更换API、不扩大绘画能力。
- 已确认代码问题：app.js 在 route/plan await 后写入旧 localTurn；图片失败回调恢复 previous，没有确认画面仍是任务开始版本。
- 方案：接收时只合并本轮拥有的字段；家庭与会话以当前值为准；使用本机会话与画面变更序号校验基图。基图变化时保留新画面并说明本轮未修改，不自动重试付费请求。
- 验收：先增加正式页面延迟模拟复现；覆盖资料修改、先到图片、旧编辑、结束/新轮次；模块测试覆盖撤销回同一版本的情况、失败不覆盖和字段所有权；最后完整发布回归。
- 数据与费用：虚构家庭与模拟API；不使用真实录音，不调用付费模型。无持久化格式迁移。
- 回退：仅撤销本批差异，不覆盖此前未提交工作。
- 仍不包括：指定turnId增量消息、逐条成长证据合并、删除防复活、Linux CI及真实图片质量。

## 复现与修复结果

1. 先加入正式页面延迟模拟，旧代码复现route/plan等待期间昵称回滚，以及图片先到后被旧clarify/chat/image/precise结果替换；结束会话丢弃迟到结果已有保护，保留为回归，并不把它算成本批新能力。
2. `mergeDrawingTurn` 只合并本轮字段，家庭资料与session保留当前值；三个证据字段沿用保守冲突比较。尚不是每条证据的版本合并。
3. `createDrawingGuard` 在每次状态提交观察画面变化，保存内存比较标记和递增序号。即使撤销回同一scene revision，旧基图请求仍过期；没有第二份可写画面，也没有持久化格式变更。
4. 路由/规划基图已变化时，保留最新画面并说明本轮未修改，不使用旧基图启动下一次付费请求；chat/clarify不回滚画面。普通回答pending阶段也不再先清空当前白板。
5. 开放图片发布再核对会话和基图；失败回调不再赋值 `state.board = previous`。原任务取消机制继续阻止旧成功/失败回调。
6. 增加跨阶段反例：route判成chat后，后台studentModel会再次覆盖路由期间的家长修改。先复现单测失败，再将证据冲突基线传到对话控制器；同时保留本轮主动清空旧证据的正常补全能力，避免所有新证据被误判成冲突。
