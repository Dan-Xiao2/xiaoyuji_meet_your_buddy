# 清空资料确认保护（2026-10-18）

## 问题与范围

此前“清空本地数据”直接执行清空，没有第二次确认。上批已实现取消在途请求和代次保护，但不能防止误点。本批只补清空入口的操作保护，沿用现有档案弹窗，不改模型API、存储格式或组件关系图。

## 实现

- `archiveControls.js`统一管理清空确认，入口检查既有家长码；`app.js`仅提供实际清空及取消任务的回调，不再自行绑定清空按钮。
- 弹窗说明删除范围与下载备份的边界，默认焦点是“保留资料”。取消和Esc关闭后返回原按钮；成功后聚焦新家庭设置的昵称输入。
- 未打开确认弹窗的表单提交无效。确认前检查主档案、旧格式档案和代次是否变化，有变化要求重新打开确认，避免按旧状态删除新增记录。这不是跨标签页原子锁。
- 同步清空失败时保留弹窗并显示错误，不伪装成成功；原资料未变化时可以再次确认重试。
