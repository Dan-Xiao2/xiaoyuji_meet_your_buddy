# 语音实验延迟拆分

日期：2026-11-01。前置：[漏词根因](2026-11-01-asr-onset-root-cause.md)。目标：把“说完到听到回答约 4 秒、打断约 2.7 秒”拆成各段，确定先优化哪里。

## 结论

1. **说完到浏览器收到回答音频平均 3.92 秒**，主要花在三段：模型首句约 1.39 秒、TTS 首帧约 1.39 秒、ASR 断句约 0.78 秒，三段合计约 92%。SDK 转交、WebRTC 传输都在 0.2 秒以内，不是瓶颈。
2. **过了 SDK 回声消除预热期之后，打断（开口到小宇静音）约 0.72 秒。** 这和之前的 2.7 秒不是同一条件下的测量，不能写成“打断从 2.7 秒改善到 0.7 秒”。2.7 秒那次没有保存事件时间线，“主要是在等预热期”只是时间上对得上的推断，未经证实（2026-11-01 校正）。
3. **另一种输入丢失：在每个会话里，小宇第一次开口后的 3 秒内，孩子说的话会被直接丢弃**，既不打断，也不进识别。这需要单独验证首次回答期间的早期插话，并保留真机回声风险。

## 延迟分解（4 次真实闭环；系统合成中文 1.8 秒；本机 LiveKit；北京地域）

均以合成语音结束时刻为 0 点。Agent 事件带本机时钟时间戳，浏览器在同一台机器上，时间可以直接相减；跨机器部署后会混入时钟偏差，不能直接沿用。

| 阶段 | 4 次样本（ms） | 平均 | 说明 |
|---|---|---|---|
| 说完 → ASR 最终结果 | 803 / 734 / 799 / 794 | 782 | server_vad 静音判定 650ms 加识别收尾 |
| ASR 结果 → 开始调用模型 | 31 / 49 / 24 / 20 | 31 | SDK 转交 |
| 开始调用 → 模型首句通过检查 | 1428 / 1361 / 1314 / 1464 | 1392 | 首 token 延迟加整句生成，含逐句安全检查 |
| 首句 → 发出 TTS 请求 | 176 / 179 / 170 / 88 | 153 | SDK 文本管线 |
| TTS 请求 → 首个音频帧 | 1386 / 1487 / 1480 / 1222 | 1394 | 明显慢于 10 月独立探测的“首块 677ms”，原因未查 |
| 首帧 → 浏览器检测到声音 | 167 / 167 / 165 / 186 | 171 | WebRTC 加播放 |
| **合计** | 3991 / 3977 / 3952 / 3774 | **3924** | |

打断（第 4 次，等过预热期后才说话）：开口 → VAD 检测 202ms → SDK 打断 375ms → 浏览器静音 138ms，**合计 715ms**。

只有 4 个样本，全部是合成语音、本机网络、同一句话，不是 P50/P95。机器当时有 Spotlight 索引负载（平均负载约 6–7）。

## 回声消除预热期（新发现）

`@livekit/agents` 1.9.5 的 AgentSession 默认 `aecWarmupDuration: 3000`。每个会话里小宇第一次进入 speaking 后 3 秒内：`interruptByAudioActivityOnce` 直接返回（不打断），`shouldDiscardInputAudio` 为真（麦克风输入被丢弃，ASR 也收不到）。只在会话第一次说话时生效一次。

实测证据（第 3 次）：小宇在 8439ms 开口，本地 VAD 在 8936–11308ms 检测到第二段语音，整段落在预热期内（到 11439ms）。没有打断，没有第二次转写，回答完整播完。这能解释本轮前 3 次打断检查为什么失败（有时间线为证）。至于之前 2.7 秒的“打断延迟”是否同样由预热期造成，因为当时没有时间线，无法确认（2026-11-01 校正）。

它的作用是防止回声消除尚未收敛时，小宇被自己的声音打断。它对儿童体验的代价是：孩子在小宇第一次回答时插话，会被静默忽略。本次**没有改默认值**，因为改小有自打断风险，必须在真机外放的条件下验证。

## 本次改动

- `voice-agent/agent.mjs`：新增 `VOICE_LAB_AEC_WARMUP_MS`。不设置时沿用 SDK 默认值；设为 `0` 关闭预热期；其他数值单位为毫秒。
- `voice-agent/companion.mjs`：新增 `llm-start`、`tts-first-request` 两个计时点（只含阶段名和毫秒）。
- `src/voice-lab/page.js`：把收到的事件类型、阶段和时间写入 `window.voiceLabTrace`（最多 200 条，不含文字和音频，不落盘）。
- `tests/livekit-live-browser.mjs`：收据新增 `breakdown`（各阶段）、`interruptionBreakdown`；打断前先等过预热期，测的才是打断本身；失败时保存事件时间线。
- `tests/voice-stream-reply.test.mjs`：同步新增的计时阶段。

验证：`npm run check` 退出 0（414 项 Node 测试加 smoke）；免费合成 WebRTC 闭环 5 组通过；真实闭环第 4 次全部通过。第 1–3 次的打断失败都由预热期造成，已保留收据。

## 费用

4 次真实闭环，每次包含 ASR 持续会话、1–2 次短回答、1–2 次 TTS，按公开单价估算合计低于 0.1 元，未查询账单。

## 建议的下一步（按收益排序）

1. **TTS 首帧 1.4 秒**：先对同一句话做独立 TTS 探测，与 10 月的 677ms 对比，判断慢在供应商还是 `pcmFrames` 分帧缓冲。若是供应商，试短首句或其他音色/模型。
2. **模型首句 1.4 秒**：输入约 1900 token。可以试缩短提示和上下文，或者先说一个很短的确认句（如“我想想”）。后者会影响对话自然度，需要产品判断。
3. **ASR 断句 0.78 秒**：静音判定 650ms 对孩子已经偏短，不建议再缩；孩子说话停顿更长，真实测试时可能还要调长。
4. **预热期**：在 iPhone 外放和真实家庭环境下测试 1000/1500/3000ms 的自打断率，再决定默认值。
