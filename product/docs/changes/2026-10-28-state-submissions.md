# 小宇记：第一批批判性复盘与第二批实施记录

## 第一批复盘结论

方向合理，但完成的是媒体生命周期边界，不能称为整个主入口已解耦，更不能等同于全双工。

| 发现 | 证据与影响 | 本轮处理 |
|---|---|---|
| 主入口行数下降不代表总复杂度下降 | 约181行从app移出，新增控制器197行。主要收益是责任可定位、可独立测试，不是总代码减少 | 修正评价标准，以状态所有权、过期结果拒收及回归场景为准 |
| 暂停并不取消整个业务回合 | app切换页面只暂停voiceSession；在途quick结果仍可经speakLatestTutorReply发起新播报。媒体代次只拒绝旧媒体回调，不拒绝新业务命令 | 保留为第三批高优先级问题；这是源码路径审查，未声称本轮已完成实际设备复现或修复 |
| 控制器仍包含产品协调 | 它同时推动白板和状态文案，app仍决定安全发布、保存及最终UI状态。这是当前适当的小边界，不是通用媒体引擎 | 暂不增加接口层，也不提前塞入LiveKit；后续接入以真实需求决定 |
| 单元测试不充分代表真实浏览器 | 第一批曾在集成时发现原生计时器绑定错误；假时钟无法发现它。原有9项也缺少同步结束/报错 | 补2项同步回调测试，11项全部通过；保留真实浏览器集成，不修改voiceSession实现 |
| 自动续听稳定性尚未完全证明 | 之前已有未定位超时；本轮完整检查又在探索流程等待回复时超时 | 保留失败记录；三轮无额外逐轮等待的诊断均通过，但不当作修复。原测试增加失败时的轮次、请求及状态快照，保留原30秒阈值和断言 |

第一批已实现：媒体代次、会话身份、重复结束保护、暂停停止与自动续听的独立控制。仍未验收：真实儿童ASR、设备尾音、iPhone熄屏、边说边听、已播语义。主入口仍有可写state，appStore并未成为唯一不可变状态源。

## 第二批为何先改这里

原来quick/complete/protected已经是受限提交，但onPending仍回传完整候选状态，由app直接覆盖。这样等待回答的入口绕过了已有边界；候选中的旧家庭资料、历史消息或画面可能重新进入当前状态。此外onPending拒收后，控制器仍会尝试请求quick API。

本轮新增7项等待阶段测试，修改前6项失败、1项通过；不是为拆文件而拆文件。

## 已落地的第二批

1. **等待阶段也用受限提交。** 只携带本轮孩子/小宇消息对、有限域变化、状态字段和比较基线，不携带可直接替换的整份应用状态。保持最新家庭资料、当前历史和无关画面；有冲突的本地域保留当前值。比较基线仍包含序列化消息快照，仅在本机使用，不是网络上传字段。
2. **普通对话统一接收。** pending、quick、complete、protected都经过app中的acceptSubmission：检查当前回合 → 应用受限提交 → 执行该阶段保存 → 现有commitState规范化、保存和渲染。拒绝的提交不进入保存/播报。没有新增状态库或第三方依赖。
3. **拒收就停止进入模型阶段。** 等待提交前检查会话；等待提交被拒收或回合被取消，不启动quick请求。
4. **回合计数和快速回复一起接受。** 计数移到纯提交逻辑，重复quick提交既不改消息，也不重复计数。
5. **绘图转聊天保留消息身份。** 新孩子输入在最初创建时获得turnId/id，pending更新同一消息，避免重复追加。

保存顺序与故障提示沿用原方案；Growth Moment、Student Model及应用快照仍分开写入，没有承诺原子事务。绘图规划、家长设置与档案替换不在本次普通对话合同迁移内。

第二批提交边界可供代码审查；探索流程偶发失败继续作为稳定性待办，禁止将本次当作可上线结论。第三批应优先统一导航离开、页面隐藏、会话结束、档案恢复/清空的停止策略，分别验证在途quick、补全、绘图及媒体回调。需要用延迟响应门控做可重复测试：停止以后不重新播报/开麦、不复活旧档案；主动返回恢复时只启动新回合。
