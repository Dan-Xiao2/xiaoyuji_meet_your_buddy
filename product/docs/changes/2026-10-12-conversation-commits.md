# OPT-01h 普通对话异步提交边界

- 状态：本批本机自动验证通过；OPT-01总项仍部分实现。
- 问题：虽然控制器在模型返回时读取最新状态，但回调和终态仍交付整份state；页面接收时直接赋值，缺少接收点的字段限制和重复提交检查。
- 场景：结果产生后、消费前发生资料修改、证据修订、会话结束或目标消息删除。
- 范围：普通聊天的quick、complete、protected三种异步提交；本机同步pending初始化继续沿用现有接口。
- 数据与费用：虚构数据、模拟API，无付费模型调用或家庭录音。

## 实现

1. 新增 `src/features/conversation/conversationCommit.js`。提交包含回合/会话标识、目标消息与阶段的预期值，以及该阶段允许的字段。
2. quick只携带指定回复文本及运行状态；complete只携带发生变化的memory/studentModel/growthEvidence和运行状态；protected携带本地安全回应，由接收端从当前状态应用安全流程。
3. 页面调用 `applyConversationCommit` 后，只有accepted才保存、计数、播报。会话、目标消息或阶段不匹配时拒绝；普通完整状态不再通过异步回调/终态替换页面。
4. 证据字段在接收时再次比较基线。发生并发修改时保留当前字段；仍是整字段冲突保护，没有逐条证据合并。
5. 阶段与消息预期值使同一提交不能再次消费；quick消费失败返回明确拒绝，控制器停止补全。模型版本、token用量和知识卡来源按明确清单保留，提交值复制后不与模型对象共享可写引用。
6. 原控制器测试通过模拟真实接收边界检查最终状态；另有直接调用控制器的契约测试，检查异步结果没有state以及越权字段无法写入。
