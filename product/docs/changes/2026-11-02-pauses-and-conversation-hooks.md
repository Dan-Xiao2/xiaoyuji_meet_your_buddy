# 孩子停顿不被抢答、每轮给话头、首句等待 10 秒

日期：2026-11-02。来源：iPhone 儿童试用反馈和测试数据（10 轮）。产品原则调整记录在 `docs/product-framework.md` 开头的 2026-11-02 条目。

## 一、第一句回答等了 10 秒

**数据：** 第 1 轮从说完到开口 10.2 秒。这一轮没有走流式语音，退回了整段 MP3（`tts`、`tts-cloud-mp3`），第一次播放失败（`tts-cloud-failed`），过了一会儿才播出来。

**原因（推断）：** 只有音频上下文处于 `running` 状态时才走流式播放，而解锁时只处理了 `suspended`。iOS Safari 在麦克风开关、音频会话切换后，会出现 `interrupted` 状态，这一轮之前恰好有一次收音被取消。退回 MP3 时，`Audio` 元素的播放不是由点按触发的，iOS 可能会拦下。

**改动（`src/services/voiceService.js`）：**
- 解锁时，只要状态不是 `running` 就尝试恢复。
- 播放前如果状态不是 `running`，先恢复，最多等 500ms，再决定走哪条路径。
- 测试数据新增 `playback-resumed` 和 `playback-not-running`，`reason` 记录恢复前的状态（`interrupted`、`suspended`、`no-context` 或 `other`）。后者计入失败统计。**下一次真机测试可以用这个确认推断是否成立。**

## 二、孩子停顿时小宇抢答

**数据与反馈：** 没有任何 `barge-in` 记录，所以不是开口打断功能误触发。断句规则是约 1050ms 静音就算说完，孩子说“其实，嗯，……”时停顿一下，就被当成说完了。

**改动：**
- `src/features/voice/utteranceCompletion.js`：`looksUnfinished` 只把“明显没说完”的识别结果当作未完成，包括以逗号、顿号、省略号结尾，或以“嗯、呃、额、然后、就是、还有、因为、所以、但是、可是、而且、或者、和、跟”结尾。“那个、这个、啊”也常出现在完整句子末尾，所以不算。`joinUtterance` 负责把前后两段拼起来。
- `src/features/voice/voiceSession.js`：识别结果被判为没说完时，先不回答，立即继续收音，界面提示“我在听，你接着说。”。这次收音如果 4 秒内没检测到说话（`noSpeechTimeoutMs`），就用已有的内容回答。每轮最多继续听 2 次；暂停或停止会丢弃暂存的半句；记录 `utterance-held`。
- 整体的静音判定（1050ms）**没有放长**，以免每一轮都变慢。

## 三、回答像在应付，孩子不知道说什么

**原因：** 提示里有多条“允许只回应不提问 / 不必提问 / 不通过反复提问延长聊天”，却没有任何正面引导，回答因此停留在复述和表态。

**改动：**
- 去掉三处“允许只回应不提问 / 不必提问”（`illustrationPlan.js` 的 `conversationPrinciple`、`conversationIntent.js` 的 `explorationInstruction`，以及 3–4 岁、4–5 岁的年龄规则）。“不考问、不连续追问、不强行二选一”保留。
- 短回答新增 `conversationHookInstruction`：
  - 每轮留一个容易接的话头，优先是具体的新细节，也可以是一个好回答的小问题；
  - 不要连续两轮都以问题结尾；不重复已经说过的事实；
  - “我不知道”是不知道答案，“嗯/哦”只是听到了，都不是拒绝；
  - 孩子说“没有了”时不再追问这件事；
  - 话头不能是邀请画画、讲故事或看图；
  - 不说自我表态式的空话。
- `dropSelfFeeling`：这类空话在提示里明确禁止后，仍然稳定出现（孩子只说“开心”时，2/2 次都出现了），所以加一道确定性过滤，删掉“听到你开心…”“小宇也…开心/高兴/暖暖”这类句子；如果删完回答会变空，就保留原句。整段输出和流式输出两条路径都过滤。

**模拟对话抽样**（3 段 × 4 轮，孩子一侧是固定台词，包含“嗯”“我不知道”“开心”“没有了”“哦”）：

| 版本 | 以问题结尾 | 空洞情绪话 | 观察 |
|---|---|---|---|
| 改前 | 6/12 | 1/12 | 单方面讲知识；“听到你开心我也很高兴”；孩子说“哦”就重复解释；孩子说“没有了”还在追问 |
| 第一版 | 12/12 | 1/12 | 像审问；重复“背着重重的壳”；把“我不知道/哦”当成拒绝；提议画画 |
| 调整后（两次抽样） | 9/12、9/12 | 1/12、0/12 | 话头具体多了（“触角像两根小天线”“雨滴在窗户上留下水痕，像小蛇在爬”）；仍会提议画画或讲故事，所以又加了禁止 |
| 加上禁止和过滤后 | 11/12 | 0/12 | 没有空话；“没有了”之后仍在追问；问题依然偏多 |

**结论（如实记录）：** 话头更具体、空话被去掉，这两点改善稳定。但“问题偏多”和“孩子说‘没有了’时的处理”仍不稳定，单靠提示词已经接近这个模型的上限。下一步可选：先判断孩子这句属于哪类（分享、提问、‘嗯/哦’、‘没有了’、情绪），再按类别选择回应方式；或换用更强的模型对比。以真实儿童试用的反馈为准。

## 四、仍像应付：按本轮给指令、换模型、逐句播放（2026-11-02 第二轮）

**反馈：** 改完之后再次真机试用，家长反馈“回答还像应付”。这一轮的 8 次对话没有失败，说完到开口中位数约 2.2 秒。

### 按孩子这句话的类型给本轮指令（`server/turnGuidance.mjs`）

先用简单规则判断孩子这句属于哪一类：只回了一声（嗯/哦/好）、说不知道、说完了（没有了/不想说了）、只说了一个感受、在提问、在分享。然后在本轮提示末尾加一条针对这一类的具体指令。另外，**如果上一轮小宇已经以问题结尾，本轮明确要求不要再以问题结尾**（只说了一个感受时例外，因为需要问一下才能让孩子说出具体画面）。之前那条通用规则“不要连续两轮提问”，模型基本不遵守。`QUICK_TURN_GUIDANCE=false` 可以关闭本轮指令，用于对比。

### 逐句播放（正式页面）

- 服务端新增 `POST /api/tutor/quick/stream`：每行返回一句已通过安全、事实、画画声明和年龄长度检查的话，最后一行带完整回答和状态。同源校验和请求校验与原接口相同。
- `llmClient`：传入 `onSentence` 时走逐句模式。还没收到任何句子就失败的话，退回整段接口；收到部分句子后才失败的话，以已经说出的部分作为回答（说出去的收不回）。
- 对话控制器：新增 `onQuickSentence`，只在当前这一轮仍然有效时才把句子交给页面。
- 语音层 `speakSentences`：每来一句，立刻请求它的语音，所有句子接在同一条 PCM 时间线上，句与句之间没有空档。一句都还没播出就失败的话，等回答完整后再走原来的整段播放。
- 语音会话 `playStreamingReply`：复用 `play` 的全部逻辑（回答开始计时、开口打断、播完自动续听、失败提示），提供 `push`、`end`、`attach`、`cancel`。开口打断标记改为在触发时读取“当前关联的回答”。
- 页面：第一句到达就开始播放，每句先在页面端做输出安全检查；有一句不通过，就停掉提前播放，回到原来的整段处理（会替换成保护性回答）。保存这一轮时关联回答编号；保存被拒绝就停止播放。
- **第一句在逗号处先切出来：** max 的第一句常常很长，所以在还没说出任何话之前，如果已经有至少 8 个字加一个逗号，就先把这个分句交出去合成语音。

**真实服务实测**（正式服务端，合成中文“天空为什么是蓝色的？”，WebSocket 识别 → 逐句接口 → 第一句语音）：

| | 首句音频到达（4 次） | 中位 |
|---|---|---|
| 之前：qwen3.7-flash 整段 + 语音 | 约 1.08 + 0.74 秒 | 约 1.82 秒 |
| qwen3.8-max 逐句（第一句整句） | 2879 / 2024 / 2007 / 2519ms | 约 2.27 秒 |
| qwen3.8-max 逐句 + 第一句在逗号处切 | 1806 / 1935 / 1819 / 1716ms | **约 1.81 秒** |

结论：**换成更好的模型之后，等待时间与之前持平。**

## 五、说话时的“电流声”（2026-11-02 第三轮真机试用）

**真机数据**（14 轮）：逐句播放已经生效，`tts-first-audio` 出现在 `quick-reply`（整段写完）之前。说完到开口中位数约 2.2 秒，换成 max 后与之前持平。开口打断 4 次，没有误打断，也没有失败。

**反馈：** 说话时一直有噪点声，像贴着话筒说话时的电流声。

**判断：** 实时识别的采集节点原先运行在一个**专门创建的 16kHz 音频上下文**里，并且接到了扬声器输出（节点本身不写输出，所以并不会回放说话声）。iPhone 的硬件是 48kHz。在 iOS Safari 上，一个运行中、采样率与硬件不一致的音频上下文，可能会让音频硬件切换工作采样率，表现为爆音或电流声。时间上正好对应“孩子说话、正在实时采集”的时候。这只是推断，**没有在 iPhone 上验证**。

**改动：**
- `src/services/realtimeAsr.js`：采集用的音频上下文改为设备原生采样率。
- `src/services/asrCaptureWorklet.js`：在采集节点里把输入降采样到 16kHz（按区间取平均，同时起到简单的低通作用，用于语音识别足够）。页面上已经没有任何指定采样率的实时音频上下文。
- 新增浏览器验证 `tests/asr-capture-browser.mjs`（已加入关键浏览器检查集）：在 48kHz 下用 440Hz、1 秒的正弦波代替麦克风，送出的结果是 15616 个 16kHz 采样（约 0.98 秒）、音高 441Hz、音量 0.353（理论值约 0.354）。

**测试日志修正：** 逐句播放之后，“整段写完”（`quick-reply`）会出现在“开始播放”之后，原来的规则会把它记到下一轮。现在它留在本轮，已用这份真机数据回放验证。

**验证：**
- `npm run check` 退出 0。
- 关键浏览器检查里，`exploration-pipeline-browser` 在第 86 行超时，其余 16 组单独运行全部通过。对照结果（负载 7–12，交替运行）：撤回这一轮的两个改动后 3/3 通过，恢复后 1/3 通过。这个用例使用浏览器自带的语音识别，不经过采集节点；测试日志的改动也不影响对话流程；之前在更早的代码上也出现过同一位置的失败。所以**倾向于认为与本次改动无关，但对照结果不能排除，列为待查。**

### 续：只有聊天时才有电流声 → 全页共用一个音频上下文

**反馈：** 改为原生采样率后电流声仍在。试用者做了对照：在家长区“麦克风 → 录一小段”录音时**没有**电流声，只有聊天时才有。

**判断：** “录一小段”只用到麦克风和一个音频上下文。聊天收音时，页面同时开着 3 个音频上下文（播放、音量条、实时采集），小宇说话时开口打断的监听还会再开第 4 个。iOS Safari 上，多个音频上下文同时处理麦克风，是常见的爆音来源。同样，**没有在 iPhone 上验证**。

**改动：**
- 实时采集节点不再接扬声器（`numberOfOutputs: 0`）。Chrome 下验证可以正常采集；Safari 下是否照常处理未知，如果不处理，实时识别会退回整段识别，测试数据里会出现 `asr-realtime-fallback`。
- `voiceService.sharedAudioContext()`：播放、音量条、实时采集、开口打断监听**共用同一个音频上下文**（就是播放用的那个，点按时已经解锁，原生采样率）。各功能用完只断开自己的节点，不关闭这个共用的上下文。`createRealtimeCapture` 和 `startBargeInMonitor` 新增 `context` 参数；不传时仍各自创建并关闭私有的上下文。
- 浏览器验证：在共用上下文上采集仍是 16kHz（16042 个采样点、439Hz、音量 0.353），采集结束后共用的上下文仍在运行。开口打断、逐句播放、测试数据、停止交互这几组真实页面流程都通过。单元测试补上了“共用的上下文不会被关闭”；`voice-capture` 和 `barge-in` 测试里的假音频节点补上了 `disconnect`。

**协作提醒：** 工作期间，同一个工作目录里还有另一方在改动（例如 `server/turnGuidance.mjs` 新增的 `responseBoundaryInstruction`、`server/qwenTutor.mjs`、`docs/team/`、`AGENTS.md` 等）。本记录只描述本会话的改动；`npm run check` 是在合并后的工作区上运行的，退出码为 0。

### 定位：电流声出在“小宇说话时”，来自开口打断的监听麦克风

**排查过程（如实记录）：** 前面几步（原生采样率、采集不接扬声器、共用音频上下文、关掉实时识别）都按“孩子说话时有杂音”的理解在改收音，没有效果。后来用排查页（`/mic-check.html`，可以逐个打开麦克风、音量检测、录音器、播放通道，还能关闭回声消除）进一步确认，试用者澄清**电流声出现在小宇说话的时候**。**关掉“小宇说话时可以开口打断”后，电流声消失**。原因因此确定：开口打断的监听在播放期间打开了带回声消除的麦克风，iOS 随即切换到通话音频（声音变闷、像从听筒出来，并带底噪）。

**改动：**
- `microphoneInput.openMicrophone({ voiceProcessing })`：设为 `false` 时，关闭回声消除、降噪和自动增益。
- 开口打断监听在**流式播放**期间用 `voiceProcessing: false` 打开麦克风，避免切换到通话音频。整段 MP3 回退时，播放不经过页面的音频图，测不到播放音量，所以仍然保留回声消除。
- 输出总线：流式播放全部经过共用上下文上的一个 GainNode，再接一个 Analyser，`playbackLevel()` 返回小宇此刻的输出音量（`pcmPlayer` 新增 `destination` 参数）。
- 检测器参考播放音量：前 500ms 估算“输出漏进麦克风的比例”（coupling）；之后的阈值是 `max(0.035, coupling × 近期输出峰值 × 1.6)`，峰值按 200ms 指数衰减，以覆盖扬声器到麦克风的延迟和房间回声。句间停顿时输出为 0，阈值回到绝对下限，孩子一开口就能检测到。拿不到播放音量时，退回原来的“预热期最大漏音 × 1.6”。
- 不开回声消除的监听麦克风，不再交给接下来的收音使用：它没有自动增益，孩子声音小时可能检测不到。打断后会以正常设置重新打开麦克风，代价是可能多丢零点几秒开头。
