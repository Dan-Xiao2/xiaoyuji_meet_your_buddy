# 扩大使用前第一批：配对入口边界

2026-11-03。基于远端 `7db7267`，在独立工作副本实现。主工作区的 UI、存储与语音在途修改未纳入本批。

## 已改行为

- 配置 `LAN_ACCESS_CODE` 后，所有 HTTP 请求和实时 ASR WebSocket 握手都需要有效配对 Cookie。本机 IPv4/IPv6、同机反向代理连接没有豁免；转发头不作为身份依据。
- 页面未配对跳转 `/pair`；API 未配对返回 `403 pairing-required`。配对入口仍可访问；同源检查、Cookie 过期和试错锁定保持。
- 配对模式关闭全部 `/api/voice-lab/*` 控制接口，即使来自已配对的本机也返回 `403 local-lab-only`。静态实验页面仍可被已配对用户读取，但不能启动实验。
- 未配置访问码的独立本机开发服务保持现状，包括本机实验。实验请另启仅监听本机、未设置访问码的服务，不要为了实验关闭家庭试点服务的配对。
- 启用配对的电脑浏览器也必须输入访问码，使用 `pilot:lan` 提供的 HTTPS 地址。凭证不包含访问码；服务重启后旧凭证失效。

## 为什么改

此前判断 TCP 连接来自 loopback 就直接允许；外部请求经同机代理转入时也可能具有该地址。本次测试证明代码分支可绕过凭证，并未部署真实外部代理或证明发生过未授权访问。当前修复的是“启用配对后仍被地址豁免”，未配置配对的本机开发服务依旧不能公开转发。

## 验证

- 改前：2 项配对单元回归失败；4 项新增真实本机 HTTP/WebSocket 测试中3项失败，分别复现页面放行、实验接口放行、实时识别握手放行。首次运行被环境禁止本机监听，获准运行后才取得上述行为证据。
- 改后：23 项相关回归通过；随后补充默认本机实验状态可访问的回归，并纳入完整发布检查。
- WebSocket 使用真实服务器的授权接线，识别提供器显式关闭；有效凭证握手成功后收到 disabled，无云端连接。HTTP 测试手工附 Cookie，不等于手机浏览器 HTTPS 配对验收。
- 完整发布检查：`TUTOR_ENABLE_LLM=false USE_CLOUD_TTS=false IMAGE_DRAWING_ENABLED=false npm run check:release` 退出0；501项 Node 检查、smoke 和17组关键浏览器流程全部通过。测试绑定本隔离版本，不代表其他在途代码或真机/真实模型质量。
- 没有付费 API、真实儿童音频或家庭资料参与；未修改真实 `.env`，未重启用户当前运行服务。

## 范围和下一批

此访问码仍是单实例家庭测试门禁，不是家庭账号。没有新增独立邀请/撤销、每家庭授权、费用预算、跨设备档案、生产部署、iPhone 锁屏验证或公网代理测试。不得据此宣称已可公开上线。

推进顺序：
1. **本批**：关闭已确认的凭证绕过，独立版本测试并提交。
2. **下一批**：根据首轮试点范围确定服务端会话/邀请边界，再加入调用并发与预算门槛。身份/额度必须由服务端确定，不接受客户端自报家庭 ID。先写无真实费用的回归，再接真实提供器。
3. **随后**：明确本机档案或云端档案的权威归属，再收口存储接口、版本冲突与删除恢复。不要同时维护两个自称权威的数据源。
4. **试点前**：固定可回滚版本，确认故障提示和无正文诊断，并由用户参与 iPhone 真机验收。范围、投入上限、数据处理同意和设备操作到需要时逐项确认。

待用户选择：首轮是否接受邀请制、iPhone 前台网页、本机档案可导出；跨设备档案或锁屏持续语音若为首轮必需，需调整下一批顺序。本批不预设该选择已批准。
