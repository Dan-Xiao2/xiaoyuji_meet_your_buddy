# 前端边界第二批：普通保存入口与失败反馈

日期：2026-10-30。接续第一批与原有 A/B/C 未提交修改，不回退既有工作。

## 本批完成的边界

新增 `src/app/applicationPersistence.js`，集中普通应用写入：状态快照、模型资料、成长片段和事件、会话开始/结束、线下观察、珍藏。主入口负责生成输入、确认回合仍有效和呈现结果；服务负责调用既有存储适配器并返回结果。成长输入函数改为 `createGrowthMomentInput`，不再暗中写库。

结果包含 `ok`、`operation`、`completed`、失败时的 `failedAt/error`，以及本次返回的 `moment`。`completed` 只表示底层函数已正常返回，不意味着每步都修改了数据：例如过期或已删除的成长片段仍由原有 revision/session/家长修订规则拒绝。`moment` 保留已成功返回的记录身份，即使后续模型或事件写入失败，也不会把它误当作未创建。

状态快照仍由 appStore 订阅触发，但实际写入经过同一服务。`isSnapshotSaved(state)` 只认可最近一次同步主存储写入且对象完全相同的快照；不表示 IndexedDB 备用副本成功。备用副本继续使用已有独立提示。

具体行为：

- 资料保存检查当前快照与模型资料的结果，失败不显示“资料已保存”；取消原有第二次重复写同一状态快照。
- 珍藏失败显示明确提示，不显示成功。成功只刷新画面，不再为只改档案标记而提交整份应用状态。
- 结束会话先停止互动，写入异常不再中断后续切页；显示“聊天已结束，但记录未完整保存”。开始新会话保存失败时不自动续听，仍允许手动操作，顶部失败提示保留。
- 观察保存失败不清空输入或合上观察面板。
- 第一条成长记录写入失败时，后续补全只更新模型，不创建替代成长片段。若记录写入成功而后续写入失败，补全使用实际已存的同一身份和版本。
- 普通写入错误统一触发原有顶部提示；一次后续快照成功不会擅自隐藏此前未解决的失败。

## 明确保留的限制

**这不是跨记录事务。** 每个底层操作仍独立读写整个 localStorage 档案；state、model、moment、event、session 仍可能只保存一部分。服务不自动重试、回滚或补写丢失事件。内存状态也可能已发布但没有完整保存；“看到页面变化”不能作为保存成功的证据。尤其观察等多步骤操作，部分成功后的人工重试尚不保证幂等，不能把保留输入等同于可安全无限重试。

恢复、导入、编辑/删除档案、清空仍走既有专用确认、校验、成对写入日志和代次切换。启动恢复也不依赖本服务。未把这些流程机械地合并为普通保存；它们在 `archiveControls`、`archiveRecovery`、`localPersistence`、`indexedArchive` 中的低层写入仍存在。

`appStore` 订阅仍负责触发保存与渲染；render 仍读档案。尚未做页面拆分、按区域刷新、统一输入协调器、严格单向视图或存储格式迁移。同代次跨标签页并发冲突、崩溃时成组恢复、旧手机性能仍待解决。原来的异步身份与取消保护保持，不由保存服务代替。

下一项存储工作应先确定普通操作的提交单位，让状态与档案变更在同一提交中成功或失败，并设计幂等身份及恢复策略；不能直接把会轮换档案代次的“替换档案”函数用于每次普通保存。本批不预先增加交易框架或新的全局状态仓库。
