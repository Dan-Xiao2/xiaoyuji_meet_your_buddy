# 小宇记发布质量与人工验收

> 自动测试证明软件按约定运行；真实模型评测比较供应商表现；真机和家庭验收判断产品是否真的可用。三层不能互相替代。

## 1. 自动发布门禁

- 本地：`npm ci` 后执行 `npm run check:release`。
- GitHub Actions：`.github/workflows/release-check.yml` 在每个 Pull Request 和 `main` 推送时执行同一命令。
- CI 不读取正式 API 密钥，不调用付费模型，使用虚构数据和关闭的云服务。
- GitHub 仓库管理员需要在分支保护中把 **Release check / release-check** 设置为 required status check；工作流文件本身不能禁止管理员绕过合并。

发布检查失败时，不得用“本机通过”替代。浏览器缺失、依赖没有锁定、测试不稳定都属于发布失败。

## 2. 真实模型 benchmark

真实评测不会被 CI 自动调用。运行前确认测试内容全部为虚构数据，并在 `.env` 或复制后的价格配置中填写当前账号单价。

```bash
npm run eval:model
npm run eval:model:images
```

可选参数：

```bash
node scripts/benchmark-real-model.mjs --live --allow-paid-api --repeats=3 --pricing=benchmarks/pricing.local.json
```

结果写入 `reports/real-model/<时间>/report.json`。图片评测还会保存原始输出，必须逐张人工查看。报告记录：

- 实际请求的文本、图片和审核模型。
- 每轮总响应延迟 P50/P95，不把它冒充首音延迟。
- 固定话题跟随率和重复追问率。
- token 使用量。
- 价格配置完整时的估算成本；未配置时为 `null`，不是零成本。
- 开放图片创建与编辑是否通过当前自动审核。
- 每条结果的人工复核状态。

初始门槛是话题跟随率不少于 80%、重复追问率不高于 20%、无模型 fallback；图片模式还要求编辑成功率不少于 80%。样本很小，只用于回归和 API 横向比较，不能当成产品效果证明。

## 3. 真机验收

每次语音链路、浏览器权限或设备选择发生变化后，至少覆盖：

| 设备 | 浏览器 | 麦克风 | 必查 |
|---|---|---|---|
| MacBook | Chrome/Safari | 内置麦克风 | 不跳转 iPhone；选择被保存；停止后麦克风释放 |
| iPhone | Safari | 手机麦克风 | 权限恢复；锁屏/切后台；连续三轮不丢首字 |
| Android | Chrome | 手机麦克风 | 权限拒绝与恢复；连续对话；扬声器回声 |
| 旧平板 | 系统浏览器 | 内置麦克风 | 按钮可达；画面不遮挡；长时间会话不明显变慢 |

每台设备使用同一组 10 条虚构话语，记录识别正确数、需要重说次数、停止说话到首声的时间、错误输入设备和断线。不要发送真实家庭录音；只有本机试听，记录结果而不是录音文件。

## 4. 幼儿语音验收

- 前提：监护人明确同意、成人全程在场、孩子可以随时停止。
- 不诱导透露姓名、学校、地址、照片或秘密。
- 不保存原始音频；观察者只记录是否听懂、是否重说、是否出现不舒服或依赖性表达。
- 每次 5–10 分钟，不要求完成任务，不用奖励延长使用。
- 若出现危险建议、要求保密、连续三次听不懂、孩子明显受挫，立即停止并记录。

核心观察：孩子是否知道什么时候可以说话、小宇是否跟住当前话题、回答是否容易听懂、打断是否有效、白板是否真的帮助理解。

## 5. 家庭试用

建议先做 5–8 个家庭、两周、小范围成人陪同试用。首要问题不是“喜欢吗”，而是：

- 家庭是否主动开启第二次会话。
- 家长是否愿意保存、纠正或删除成长片段。
- 一周后是否主动回看。
- 某次回看是否带来一次更好的亲子交流。
- 语音、延迟、重复问题或错误记录是否让家庭放弃。

试用记录使用 `docs/templates/manual-validation-record.json`，只保存最小必要信息。页面自动记下的每次聊天结果（句数、纠正、结束方式、隔几天再来、家长回答、收藏与修改数）见 [value-measurement.md](value-measurement.md)，从家庭设置 → 设备与测试 → 测试数据导出。试点的同意书、观察记录填写方法、访谈提纲和每周汇总见 [pilot-handbook.md](pilot-handbook.md)。真实儿童原话默认不进入 issue、截图或公开报告。

## 6. 发布判断

一次候选版本只有同时满足以下条件，才可以进入下一阶段：

1. `check:release` 通过。
2. 固定真实模型 benchmark 已运行并人工复核，失败有明确接受或阻断决定。
3. 目标设备矩阵完成，没有未解释的麦克风路由问题。
4. 涉及幼儿的功能完成监护人陪同测试，且没有严重安全事件。
5. 家庭试用价值结论与技术结论分开记录。

没有幼儿或家庭样本时，状态应写“待人工验证”，不能写“已验证好用”。
