# 小宇记产品框架与开发原则

> 本文档是小宇记当前最高优先级的产品决策依据。后续产品、内容、设计、数据和工程改动都应先与本文档对齐。若新的真实用户证据与现有原则冲突，应先记录证据并更新本文档，再修改产品。

> 2026-10-18 定位更新：用户确认“孩子愿意主动和小宇交流”是核心，优先入口是“我想让你看看我今天发现的东西”和“我有个问题”。本次更新产品原则和待验证计划，不表示运行时已完成对应改造或市场需求已验证。

## 1. 产品身份

### 儿童安全补充决定（2026-09-30）

保护优先于记录：识别出的敏感求助不自动写入成长片段、兴趣、普通备份或后续文本模型上下文；不以“帮助家长”为由自动转发可能伤害孩子的披露。先提供简短支持，不审问、不诊断、不承诺绝对保密或已通知别人。当前暂不建设敏感原文档案，直到分级权限、数据政策和专业复核明确。文本检测不能撤回已经送往云端ASR的音频，也不代表历史数据已全面脱敏。实现边界与发布门槛见 `child-safety-evaluation.md`。

- 产品名称：**小宇记**
- AI 陪伴角色：**小宇**
- 核心表达：**记录孩子自己的小宇宙。**
- 当前价值主张：**小宇是孩子探索日常世界的伙伴：听懂孩子的发现，陪他琢磨问题，把值得留下的瞬间留给家庭。**
- 核心原则：**让小宇跟得上孩子的好奇心，而不是让孩子走一套预设流程。**
- 价值顺序：孩子当下被听懂、得到有用回应；家长随后看见并选择留下孩子的视角；知识库支持适龄、可靠、有边界的回应。成长记录不是对话的任务或诱导提问的理由。
- 第一阶段整体年龄：0-6 岁；按发展阶段提供不同交互，不让婴儿和学龄前儿童使用同一种界面。
- 后续年龄方向：7-13 岁，但需要独立的学习目标、知识模型和产品体验，不作为当前 MVP 的自然延长。
- 第一购买者和管理者：家长或主要照护者。
- 直接使用者：家庭共同使用。3-6 岁以孩子直接语音为主，家长和其他照护者也可以补充观察；0-3 岁以家长辅助记录和亲子互动为主。
- 幼儿园的角色：早期真实测试和触达家庭的渠道，不是第一阶段的核心付费用户。

### 年龄分层

| 年龄 | 主要使用者 | 交互重点 |
|---|---|---|
| 0-1 岁 | 家长 | 记录声音、动作和有意义的第一次；获得回应性照护与亲子互动建议 |
| 1-2 岁 | 家长辅助、孩子参与 | 简单声音回应、模仿、指认、儿歌和亲子游戏 |
| 2-3 岁 | 孩子短时参与 | 极短语音轮次、看图说话、动作和现实物品任务 |
| 3-6 岁 | 孩子直接使用 | 语音陪伴、故事、好奇问题、情绪表达和按需白板 |

0-6 岁共享同一条成长时间线，但年龄阶段、对话长度、家长参与程度、允许记录的证据和指导方式必须不同。工程实现顺序仍先验证 3-6 岁孩子直接语音，再补齐 0-3 岁家长辅助模式。

## 2. 我们最终想做什么

小宇记希望成为一个真正认识孩子、陪孩子表达和探索、又能把数字互动重新连接回家庭与现实世界的成长伙伴。

长期价值不来自“能回答多少问题”，而来自四件事：

1. **听见孩子**：让表达能力有限的孩子也能自然说出经历、问题和想象。
2. **延展好奇心**：把一句话发展成一个问题、故事、图画或现实探索。
3. **持续记住**：用结构化成长记忆理解兴趣、表达变化、尝试方式和需要的支持。
4. **连接家长**：把有意义的线索转化成家长可以继续聊、继续陪的入口。

未来可以探索玩偶或桌面伙伴加小屏幕的专用硬件，但硬件只是更自然的入口。产品的核心资产始终是对话设计、内容体系、结构化成长记忆和家长价值。

### North Star Goal：孩子愿意带着发现和问题来，小宇能够接住并跟随

第一阶段先验证孩子能否主动分享或提问，小宇能否听懂、直接回应，并在孩子纠正、换话题或停止时尊重其意图。孩子不需要为了报告、课程、画图或收集数据而继续说话。自然再次使用与家长认可均需真实家庭验证，不能用聊天时长替代。

### 长期家庭价值：让孩子的成长被保存、被看见、被重新想起

0-6 岁的孩子变化很快。从婴儿第一次用动作和声音回应，到幼儿反复追问的问题、突然喜欢上的事物、讲故事的方式和对朋友的关注，这些片段都可能很快消失在日常生活里。家长真正的痛点不只是“不知道今天聊什么”，也是回头时才发现，自己没有留下孩子当时如何表达、观察世界、提出问题和慢慢改变的记录。

在有价值的交流基础上，小宇记的长期留存目标是：

> **把散落在日常对话里的成长瞬间，变成一条家长能够理解、回看和珍藏的时间线。**

它不是传统日记，也不是儿童能力报表。它记录的是孩子自己的视角：

- 曾经问过哪些问题，后来问题怎样变得更具体或更复杂。
- 一段时间里喜欢什么，又在什么时候转向新的关注点。
- 怎样描述朋友、家庭、自然和自己遇到的事情。
- 故事、想象、表达长度和解决问题方式发生了什么可观察变化。
- 哪些原话、图画、白板片段和现实探索值得家长长期保存。

当有值得保存且适合记录的内容时，系统才进入以下循环；不是每次会话都必须形成成长卡：

```text
捕捉真实成长片段
  -> 保留孩子原话和发生时间
  -> 归入兴趣、问题、表达或探索线索
  -> 在有足够证据时识别变化
  -> 用“过去和现在”讲清成长故事
  -> 在合适的时刻重新呈现给家长和孩子
  -> 促成一次新的亲子对话或共同回忆
```

家长获得的情绪价值应来自真实内容，例如“原来她三个月前一直在问月亮，现在已经开始自己解释影子”，而不是来自 AI 编造的感动文案、能力分数或夸张结论。

### North Star Metric

第一阶段暂不设单一增长数字。用两层行为证据验证价值，不把任一层当作另一层的替代：

- **孩子当下价值（主验证）：** 在孩子主动分享或提问的会话中，观察回应是否跟题、孩子纠正是否被采纳，以及孩子是否自愿继续、结束或以后再次发起。记录有效与失败会话的分母、家长提示程度和退出原因；自然结束不算失败。
- **家庭长期价值（次验证）：** 家长是否自愿保存、修正或回看真实片段，是否促成后续亲子交流。记录是可选结果，不设置每日条数或每次必存指标。
- **护栏：** 安全、理解错误、反复追问、等待、成人代操作和数据可控性单独评估；不以长时使用、签到、生成图数量或报告数量证明成功。

## 3. 小宇是什么，不是什么

### 小宇是

- 愿意耐心听孩子说话的伙伴。
- 帮助孩子把零散表达说得更完整的引导者。
- 用简短问题、故事和视觉白板扩展好奇心的启发者。
- 基于证据记录兴趣和变化的成长记录者。
- 帮助家长找到后续沟通入口的连接者。

### 小宇不是

- 父母、老师或同伴的替代品。
- 儿童版 ChatGPT 或什么都回答的智能音箱。
- 拍题、刷题、抢跑识字和应试训练工具。
- 心理医生、医学诊断工具、同龄排名或未经验证的能力测评系统。
- 监控孩子、判断孩子是否“乖”或替家长审问孩子的工具。
- 通过依赖、秘密或情感承诺留住孩子的虚拟朋友。

任何新功能如果让产品更接近右侧这些角色，应默认不做。

## 4. 第一核心使用场景

### 孩子主动分享发现或提出问题

优先验证两个自然开场：“我想让你看看我今天发现的东西”和“我有个问题”。不要求放学后使用，也不要求讲述幼儿园经历。分享可以先用语音；看照片是待实施的独立能力，附件可保存或图像可生成不代表模型已经看到了孩子分享的东西。

孩子不需要拥有手机。家庭使用自己的手机或家里的旧平板打开小宇记，把设备放在桌面支架上。首次使用由家长一次性完成家庭和儿童资料设置，之后任何已登记的家庭成员都可以直接进入共同对话。

```text
家人打开小宇记
  -> 直接进入“和小宇聊”主页面
  -> 孩子主动分享发现或提出问题，家人可协助
  -> 小宇接住分享，或先直接回答问题
  -> 只有理解受阻时澄清；有帮助时才使用视觉或邀请现实观察
  -> 孩子可继续、纠正、换话题或停止
  -> 会话自然结束
  -> 有合适内容时，家庭可选择保留与回看
```

家庭资料只在首次使用或主动进入设置时修改，不在每次对话前重复填写。孩子进入会话后，不应面对登录、设置、复杂导航或文字输入。

### 家庭成员与说话身份

- 第一版每个家庭只建立 1 个主孩子成长档案，另外最多登记 6 位家长、祖辈或其他照护者，共最多 7 位可说话成员。
- 六个成人名额不包含主孩子；第一版不允许添加第二个孩子档案，多孩子创建、选择和切换留到后续阶段。
- 每条语音或文字记录必须保存说话人身份；家长反馈不能自动当作孩子原话、兴趣或能力证据。
- 当前 MVP 先提供“记住上次选择的说话人”的手动回退，保证归属真实可修正。
- 自动声纹识别属于后续能力，需要分别录入声音样本、取得明确同意、生成可删除的声纹特征，并返回身份置信度；置信度不足时必须询问或回到手动选择。
- 不保存不必要的长期原始录音，不把声纹用于身份认证、监控、推断情绪或判断家庭关系。

这是 3-6 岁阶段的第一技术验证场景，不代表 0-3 岁儿童也应独立使用同一流程。

### 网页与手机的两种呈现

当前阶段共享同一套网页代码、数据和 AI 能力，但根据设备采用两种信息层级：

- **大于 900px 的桌面网页：** 顶部保留“一起聊、成长记录、家庭设置、备份记录”四个入口，适合家长查看、演示和整理记录。
- **不大于 900px 的手机与旧平板：** 打开后只突出共同语音入口；其他功能收进左上角侧边菜单。
- **同步原则：** 两种呈现必须使用同一套页面内容、导航配置和状态，只允许导航形态与响应式排版不同；不得再为桌面和移动端分别维护功能文案或页面副本。
- **首次使用：** 仍需家长完成昵称、年龄和本机保存同意；完成一次后，手机首页可以直接开始新的自然对话。
- **技术边界：** 当前实现是独立的响应式手机界面，不等于已经开发原生 iOS/Android App。只有网页主链路和真实留存得到验证后，才评估原生客户端。

手机界面可以借鉴成熟专注类产品“一屏一个主要动作、次要功能进入侧边菜单”的组件模式，但不复制其品牌、配色、图标或游戏化机制。

### 0-3 岁家长辅助场景

家长在日常照护或亲子互动后，用一句话、一个声音片段或一张手动选择的照片记录观察。小宇记可以提供与当前月龄相符的亲子说话、阅读、动作或游戏建议，但不解释哭声病因、不判断疾病，也不替代儿保和发育筛查。

```text
家长选择孩子
  -> 记录一句观察或手动附加照片
  -> 选择当时场景
  -> 系统保存原始证据
  -> 在多次证据足够时描述正在出现的成长变化
  -> 给出一个具体、低负担的亲子互动建议
```

### 次级场景

- 睡前互动故事：短讲述、多停顿、多选择，避免长时间被动播放。
- 好奇问题探索：从孩子主动提出的问题出发，用语音和白板共同理解。
- 现实任务回访：孩子回来告诉小宇刚才找到了什么、画了什么、试了什么。
- 幼儿园安静探索角：一次一名或两名孩子，用于小范围观察和产品测试；暂不做全班课堂管理。

## 5. 标准互动结构

以下是按意图选择的原则，不是逐轮模板或必须完成的步骤：

1. **让孩子发起**：入口保持清楚简洁，不默认盘问当天经历或展示任务菜单。
2. **先回应意图**：分享时具体接住发现；提问时先给简短、适龄的答案，不用反问代替回答。
3. **必要时确认**：听不清或信息不足才澄清；不把每轮复述变成固定开头。孩子纠正后更新理解，不回到旧模板。
4. **允许不追问**：每轮最多一个必要问题，也可以没有问题；孩子只想分享时不强行延长。
5. **跟随变化**：在当前主题上扩展一点；孩子换话题或改变想法时及时跟随，不强行回到颜色、课程、故事或绘画。
6. **按需视觉化**：只有图画确实有帮助时才使用白板。
7. **按需回到现实**：合适时邀请孩子观察、尝试或与家长继续聊，不把现实行动变成每次对话的作业。
8. **自然收尾**：短互动结束，不用奖励动画诱导继续停留。

小宇应允许孩子沉默、跳跃话题、答非所问或临时改变主意。幼儿对话不是问卷。

## 6. 孩子端体验原则

### Voice-first

- 不要求孩子打字、阅读说明或理解菜单。
- 第一版允许家长使用备用文字输入排障，但不能把它设计成孩子的主要入口。
- 语音按钮必须是当前页面最明确的操作。
- 语音状态只需要表达“可以说、正在听、正在想、正在说”等儿童能理解的状态。

### Visual-assisted

- 视觉理解与视觉生成是两种能力：没收到可用图片时不能说“我看到了”；无法确定时说明限制。示意图与生成插画不是孩子真实发现的证据。
- 新的单张照片分享方向先做方案与安全验收，不默认启用。由家长开启并说明本机预览、向模型发送和长期保存的区别；儿童可在成人协助下主动分享普通物品，不主动索取人脸、身份或私人环境照片。
- 拟议流程只处理用户主动选择的一张图，可预览、取消；不持续摄像、不扫描相册。拒绝发图或识别失败时允许用语音继续，不反复要求补图。

- 2026-10-05 已确认双路径：开放想象使用图片生成与基于原图的编辑，数量、位置等可精确表达的任务继续使用结构化白板。不能把有限素材库当成全部绘画能力，也不能把图片生成当成精确对象编辑。两种路径不要求孩子选择模式。
- 图片生成是按需的异步回应；等待时保留原图并允许聊天，失败不虚构完成。只传必要绘图要求和当前画面，不附带家庭档案或录音。开放图片的内容安全、真实速度、连续编辑一致性必须另行验收，不能因接口接入就宣称成熟。

- 白板是小宇的纸和笔，不是持续播放动画的屏幕。
- 会话开始前不显示白板，只显示作为主要语音按钮的小宇；有真实视觉内容后，白板才展开。
- 白板展开时，小宇缩到左下角成为持续语音入口，孩子可以在保留当前画面的同时继续追问。
- 图画、文字、数量、故事场景和关系图必须跟随当前对话出现。
- 视觉内容要简洁、可指认、可讨论，不能只追求装饰效果。

### Screen-light

- 不要求家庭在每次开始前选择 5、10 或 15 分钟，也不显示倒计时；互动可以随时开始和结束。
- 产品仍以短时、自然互动为设计目标，在合适时主动建议回到现实活动，但不强制切断正在进行的家庭对话。
- 产品要主动创造离开屏幕的理由。
- 现实活动、亲子沟通、同伴游戏和身体运动始终比留存时长更重要。

### 界面

- 孩子初始页只保留小宇语音入口；白板不占空位，也不提前出现。
- 进入视觉讲解后，页面以完整白板为主，只保留左下角小宇、当前说话人和结束入口。
- 不展示技术状态、模型名称、内容设计依据、开发计划或成长分析。
- 不用大量按钮让孩子选择“模式”；故事、问题和聊天可由自然语言进入。
- 文案使用短句、具体词和口语，避免抽象教育术语。

## 7. 家长端体验原则

家长端的任务只有四类：开始、理解、继续陪伴、管理。

### 家长真正需要看到的内容

- 今天孩子主动提到了什么。
- 一句值得记住的孩子原话。
- 最近反复出现的兴趣和问题。
- 孩子表达、尝试和探索方式发生了什么可观察变化。
- 一条按日期组织、可以回到过去查看的成长时间线。
- “以前和现在”的真实对照，例如问题、兴趣或表达方式的变化。
- 每周或每月自动整理的成长回看，而不是每天重复生成类似报告。
- 家长今晚可以接着问的一句话。
- 一个简单的现实世界亲子活动。
- 数据保存、下载和删除入口。

### 家长不需要看到的内容

- Prompt、模型、数据库和白板命令等开发细节。
- “内容设计依据”“试点闭环”“班级观察模式”等内部工作模块。
- 大量教育理论和长篇报告。
- 没有证据支持的性格、能力或情绪结论。
- 给孩子排名、打分或制造焦虑的成长百分比。

家长摘要应优先帮助家长继续连接孩子，而不是证明 AI 做了很多事情。

## 8. 内容领域

内容以中国学前儿童常见的发展领域为基础，但不做课程表和考试体系。

1. **语言与表达**：讲述经历、描述细节、复述故事、表达选择和原因。
2. **社会与情绪**：朋友、轮流、等待、求助、冲突、开心和不开心的表达。
3. **科学与自然**：动物、植物、天气、影子、声音、材料、比较和简单因果。
4. **艺术与想象**：画画、颜色、音乐、角色扮演、故事改编和开放想象。
5. **健康与生活**：身体动作、节奏、生活自理、安全习惯和日常参与。
6. **早期数感与逻辑**：在积木、分享、分类、顺序和真实物品中自然出现，不做刷题训练。

### 发展资料依据

- 0-3 岁优先参考国家卫生健康委婴幼儿早期发展资料中的大运动、精细动作、语言、认知和社会交往框架。
- 3-6 岁优先参考教育部《3-6 岁儿童学习与发展指南》中的健康、语言、社会、科学和艺术领域。
- 学术和官方资料用于建立年龄阶段参考、观察问题和家庭活动建议，不用于自动诊断、百分位排名或给孩子贴固定标签。
- 所有阶段判断必须保留资料版本、适用年龄、证据数量和家长确认状态；资料更新时可以追溯和重算。

### 内容设计可用的材料（按需选择）

- 一个孩子容易进入的具体情境。
- 一个真正允许多种回答的表达点。
- 一个可选的视觉表达。
- 一个现实世界的小行动。
- 一个可记录但不用于贴标签的观察点。
- 一个帮助家长继续聊的提示。

这些是设计素材，不是运行时必填输出。普通问题可以只回答，分享可以只回应，不必附带图画、追问、现实任务、家长建议或成长证据。

## 9. 故事原则

- 小宇一次只讲一小段，然后停下来让孩子预测、选择、补充或表演。
- 优先原创、适龄、日常、可延展的故事，避免默认调用受版权保护的完整故事文本。
- 不以恐吓、羞耻、服从或失去关爱推动情节。
- 故事不应持续占住孩子；结尾尽量转化为画一画、演一演、找一找或讲给家长听。
- 孩子是共同讲述者，不是音频播放器的听众。

## 10. 成长记忆原则

结构化成长记忆可能形成连续价值，但不是已经建立的护城河。必须验证相关记忆是否改善回应与家庭回看；过时、不相关或被纠正的记忆不能强行带入当前话题。

### 三层记忆

1. **原始证据**：孩子原话、问题、选择、会话时间、完成的现实活动和家长观察。
2. **结构化模型**：兴趣、正在发展的表达方式、反复出现的困难、偏好的支持形式和变化轨迹。
3. **当前会话上下文**：只选取本次最相关的少量记忆，帮助小宇调整提问和解释方式。

### 成长片段是最小产品单位

每一条值得长期保存的记录都应形成一个可回看的 Growth Moment，至少包含：

- 发生日期和所属会话。
- 孩子原话或可验证行为。
- 当时关注的问题、人物、兴趣或情境。
- 可选的白板画面、故事片段或现实活动。
- 家长手动选择附加的照片及照片说明；系统不得主动向孩子索要照片。
- 证据来源和系统推测的明确区分。
- 家长是否确认、补充、珍藏或删除。

成长时间线由这些片段组成。系统不能只有不断覆盖的“当前画像”，否则家长只能看到现在，无法看到孩子是怎样走到现在的。

### 必须区分

- “孩子说了什么”和“系统推测什么”。
- 一次行为和长期趋势。
- 未验证线索和家长确认的信息。
- 学习支持需要和人格评价。

### 允许记录

- 孩子主动提出的问题和原话。
- 持续兴趣、故事偏好和现实探索。
- 可观察的表达长度、复述方式、尝试策略和提示依赖变化。
- 经过多次证据支持的理解困难或常见误区。
- 家长补充的现实活动观察。
- 经家长选择保留的白板片段、故事和成长卡。
- 家长手动附加到具体成长片段的照片、日期和说明。
- 兴趣、问题和表达线索首次出现、反复出现、淡出或转变的时间。

### 成长阶段观察

阶段观察只能在多条、跨时间、可追溯证据基础上生成。内部可以参考儿童发展研究和官方指南，家长端统一使用以下非排名语言：

- 刚刚出现
- 正在练习
- 逐渐稳定
- 经常主动使用
- 暂时没有足够记录

每条阶段描述都必须回答“看到了什么、证据在哪里、家长可以做什么”。当出现持续且值得关注的信号时，只建议家长携带具体记录咨询儿保医生或专业人员，不由 AI 作医学结论。

第一版资料与输出协议已结构化在 `skills/xiaoyu-growth-companion/`：

- `references/source-registry.json` 登记来源、适用年龄、证据类型、版权用途和复核日期。
- `references/knowledge-cards.json` 保存可机器读取的分龄陪伴与现实活动卡。
- `references/growth-observation.md` 定义内部证据门槛、家长显示语言和不可越过的解释边界。
- `references/safety-escalation.md` 区分普通成长观察、发展担忧和需要成人或专业支持的情形。

来源中的年龄目标和里程碑只用于设计适龄互动，不是产品量表。阶段词描述的是小宇记已保存证据的充分程度，不表示孩子在医学或教育意义上的发展水平。任何门槛都必须经过真实家庭纵向试点校准后，才可接入家长端自动生成。

### 禁止形成

- “不聪明”“不合群”“懒”“注意力差”等固定标签。
- 医疗、心理或发展障碍诊断。
- 单次情绪推断出的长期性格结论。
- 为增加使用时长而建立的情感依赖画像。

所有成长结论都应能追溯到证据，并允许家长查看、修正、下载和删除。

## 11. 家长摘要的语言规则

摘要必须使用证据语言：

- 推荐：`孩子提到今天和一个新朋友搭了积木。`
- 不推荐：`孩子今天成功交到了新朋友。`
- 推荐：`最近三次互动中，孩子都主动选择了动物主题。`
- 不推荐：`孩子属于视觉型学习者。`
- 推荐：`这次在一个提示后，孩子补充了人物和地点。`
- 不推荐：`孩子的语言能力提高了 20%。`

AI 听到的是孩子的表达，不一定是完整事实。家长摘要不能把推测写成事实，也不能制造诊断感和比较焦虑。

## 12. 安全、隐私与关系边界

- 由家长创建和管理儿童档案，并明确同意数据保存方式。
- 默认最少收集；MVP 优先本地保存，可由家长主动导出或删除。
- 现有照片政策仍是家长手动附加到成长片段，不做人脸识别、不扫描相册、不公开分享。拟议的“给小宇看一张图”需单独明确发送权限、第三方处理、临时文件清理、失败取消及保存选择并验收后才能启用；本次文档更新不授权上传家庭照片。用于回答不等于同意长期保存。
- 不默认保存连续原始录音；若未来需要，必须单独说明用途和保存期限。
- 不要求孩子提供真实姓名、住址、幼儿园名称、联系方式或其他不必要身份信息。
- 小宇不能要求孩子保守秘密，不能说“只有我懂你”，不能鼓励孩子疏远家长或朋友。
- 小宇不能承诺自己是真人、最好的朋友或永远陪伴孩子。
- 遇到安全、伤害或严重不适相关表达时，小宇应保持平静，鼓励孩子尽快告诉身边可信任的成年人；不能自行调查、诊断或作出确定事实判断。
- 正式对外试用前，需要针对中国未成年人个人信息保护、监护人同意、数据存储和第三方模型调用进行专门合规审查。

## 13. 产品和技术架构原则

```text
孩子当前发现或问题
  -> 安全边界内理解意图（相关历史和知识仅作辅助）
  -> 简短回应；必要时澄清、展示或共同观察
  -> 孩子继续、纠正、换话题或停止
  -> 合适内容按保存规则成为可修正的记录与家长回看
```

上图是产品责任顺序，不是当前运行架构。实际组件与接通能力以 `docs/architecture/` 为准；本次不新增图片理解服务或改写现有运行架构图。

- ASR、LLM、TTS 和白板渲染是不同职责，允许分别选择模型和供应商。
- 模型供应商必须可替换，业务逻辑不能完全绑定某一家 API。
- LLM 负责理解、规划和生成结构化指令；前端负责稳定渲染，不直接执行任意模型生成代码。
- 关键安全规则、时长控制、数据权限和删除逻辑不能只依赖 Prompt。
- 内容知识必须经过来源登记和结构校验；运行时只能使用许可用途与产品场景兼容的资料。
- 先保证真实主链路可靠，再增加模式、角色和内容数量。

## 14. 当前 MVP 范围

### 必须做通

- 家长在共享手机或旧平板上快速开始一次儿童会话。
- 3-6 岁孩子从真实分享或问题开始，用语音自然交流；纠正、换题、拒绝和结束有效。
- 先保证语音和回答可靠；白板按需使用，失败不阻断继续聊天，不虚构看见或画完。
- 合适内容按明确保存规则形成真实记录，家庭能修正、珍藏、下载和删除；不为了摘要诱导孩子表达。
- 保留安全降级、服务不可用提示和成人备用输入。

### 下一项待验证能力与后置扩展

- 单张照片分享与视觉理解先完成权限、事实性、安全和失败回退设计；不能作为当前已接通能力宣传。先用虚构或非敏感素材测试，再经家长同意做家庭验证。
- 保留已有故事、精确白板、开放绘图和成长回看，不撤回现有可用功能；暂缓扩充素材、角色与任意绘图范围，除非真实分享或提问被该缺口阻断。
- 0-3 岁家长辅助、7-13 岁、成长阶段观察和更复杂的纵向分析属于后续范围，不再作为当前探索主链路的同时交付要求。

### 当前不做

- 自研硬件和量产供应链。
- 全班课堂管理、教师工作台和园所汇报系统。
- 完整学科课程、作业和刷题系统。
- 儿童社交网络、公开分享或孩子之间直接通信。
- 摄像头持续观察、表情识别和自动心理判断。
- 复杂积分、连续签到、排行榜和刺激留存机制。
- 在没有真实验证前扩展大量角色、游戏和模式。
- 7-13 岁学科教学、知识掌握度和错因诊断产品。
- 哭声病因判断、排便或饮食诊断、医学结论和自动同龄排名。

## 15. MVP 验证指标

第一阶段验证“是否值得继续”，而不是追求注册量。

- 先小范围成人陪同试用，招募规模和观察周期在试用前确定；不得把招募数量或固定时长当作产品通过门槛。
- 孩子能带来自己的发现或问题，在家长少量帮助下得到相关回应；记录发起是自主、提示还是成人代操作。
- 孩子可自然继续、纠正、换题、结束，不必达到固定轮数；在有再次使用机会时是否自愿回来需要单独观察。
- 家长能在 30 秒内理解摘要，并认为其中至少有一条值得继续聊。
- 家长愿意珍藏或回看至少一条记录，并认为它捕捉到了自己可能错过的孩子视角。
- 跨时间证据足够时才展示变化；没有变化证据也允许单次发现有价值，不为通过验收编造成长。
- 下一次互动能合理使用过去的兴趣或表达证据，让家长感到“小宇记得孩子”。
- 至少一部分互动成功转化为画、找、搭、说或身体活动。
- 家长能理解数据保存方式，没有明显隐私和关系替代担忧。
- 语音识别、回复等待和白板呈现不频繁打断孩子的注意力。

### Go / Pause / No-Go

- **Go（继续小规模验证，不等于上市）**：孩子自主发起和相关回应在多个家庭重复出现，家长接受使用方式；家庭回看价值另行记录，不据此推断付费意愿。
- **Pause**：语音/等待掩盖了需求判断；或孩子主要索要刺激、需要成人连续代聊。先区分技术故障与价值不足，再修复或收窄场景。
- **重新评估定位**：技术可用后仍长期依靠成人催促；或孩子喜欢而家长不接受。记录无价值时先复核家庭价值，不自动否定孩子交流价值，也不能直接宣布商业模式成立。
- **停止相关能力**：出现严重安全问题、未经同意的数据发送，或无法解释和控制的隐私风险，先停止并修复，不用参与度抵消。

## 16. 开发决策检查表

每个新功能、页面或内容进入开发前，必须回答：

1. 它解决的是孩子、家长还是内部开发者的问题？
2. 孩子或家长会在什么真实时刻使用它？
3. 它是否帮助孩子表达、思考、探索或回到现实世界？
4. 它是否帮助家长更好理解并继续陪伴孩子？
5. 它是否需要留下记录？若不需要，能否减少收集而不损害孩子当下价值？
6. 它依据什么真实证据，而不是团队想象？
7. 它是否增加了不必要的屏幕时间、按钮、文字或操作步骤？
8. 它是否把推测包装成事实、评分、标签或诊断？
9. 它会收集什么儿童数据，是否可以少收、晚收或不收？
10. 它能否在当前 MVP 主链路中被真实测试？
11. 如果不做它，核心体验是否仍然成立？
12. 若涉及年龄阶段判断，它依据哪一份研究或官方资料、多少条真实证据，以及是否允许家长修正？

第 2、6 项必须说明场景和证据状态；没有证据只能作为有边界的验证任务。第 3、4 项至少服务一方且不得损害另一方。第 5 项是数据必要性检查，不要求每个功能都产生成长记录。安全、数据可靠性修复可作为基础任务，不必伪造直接增长价值。

## 17. 界面发布检查表

### 孩子端

- 不识字的孩子是否知道下一步做什么？
- 页面是否只有一个明显的主要动作？
- 开始前是否没有无关白板内容？
- 语音状态是否清楚且不依赖长文字？
- 是否没有开发术语、模型状态和复杂模式按钮？
- 手机和平板上是否都能看清、点到且没有重叠？

### 家长端

- 家长是否能在几秒内看到今天最重要的一件事？
- 是否优先显示孩子原话、可观察变化和后续沟通建议？
- 是否让家长看见时间、原始片段以及变化是如何发生的？
- 图表是否解释成长轨迹，而不是制造分数感？
- 页面是否避免教育术语、内部策略和长篇说明？
- 家长是否能找到保存、下载、修正和删除数据的入口？

## 18. 路线原则

### 关键缺口与状态依据

真实语音理解与等待、话题跟随和纠正、视觉是否有助理解、记录是否有家庭价值，都还需要分别验证。单张照片分享尚未作为完整主链路验收；安全、状态一致性、档案可靠性和发布检查仍有未完成项。

本框架不再维护易过时的第二份功能完成清单。当前实现和测试证据见 `docs/development-log.md`；具体任务与开放项见 `docs/product-optimization-plan.md`。历史演示或自动测试通过不能替代真实体验。

### 执行顺序

1. 保留安全、状态一致性与数据恢复的工程底线；这些不因定位更新而降级。
2. 在现有语音入口验证“分享发现 / 提出问题”，优先修复听错、等待、模板追问与忽略纠正，先不扩功能广度。
3. 明确单张照片分享的数据边界，用非敏感素材验证接收、理解、拒绝/取消与语音回退；未实现前不宣传“看见”。
4. 通过同一问题的纯语音与按需视觉对照，判断白板是否真正有用，不将“任意画图”设为核心体验前提。
5. 在成人陪同下验证孩子主动性、家长接受度、自然再使用与可选回看；小样本不作为普遍效果结论。
6. 验证相关记忆是否帮助继续探索；再投入跨周叙事和家庭保存价值。健康、安全等专业边界仍需复核。
7. 价值和成本获得证据后，才评估扩龄、成长阶段观察、商业化或硬件；不同时开发宠物版或综合育儿平台。

不要用硬件掩盖软件体验的问题，也不要用功能数量代替真实儿童和家长验证。
