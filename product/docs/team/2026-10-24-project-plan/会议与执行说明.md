# 小宇记团队开发计划与每周执行方式

编制：2026-10-24。明天会议：2026-10-25。目标用户已确认先为中国大陆3–6岁家庭。团队容量尚未确认，“至少周末半天”是此前初步约定，不作为已经承诺的工时。

## 1. 明天要决定什么

这次会议不是把所有功能排进下个月。需要让三位开发者看清系统、选择负责范围、确定投入和首项任务，约定怎样复核与集成。

会议结束时至少得到六项结果：

1. 三人的每周可投入小时、通常时段、交叉复核时间；不能到场时怎样提前说明。
2. 三人各自愿意主导的主线和一个备用复核领域。
3. 共同上手任务TEAM-01，以及上手后每人最多一项首任务。表中的“候选”不等于本周承诺。
4. 每项任务一名负责人、一名不同的复核人、可展示交付和验收条件。
5. 唯一任务主表、Git分支/审核规则、周会时间及阻塞处理方式。
6. 初始评测预算由谁确认、账号归谁管理、远程试用谁能批准。

所有任务默认排队，负责人待认领，估时与目标日期留空。现有实现写在“任务验收”的基线列，不把本轮规划任务全未验收误读成产品从零开始。

## 2. 从整体理解当前软件

小宇记当前是原生JavaScript网页加Node服务，已有语音、文字、受限白板、开放图片适配、成长档案与备份原型。它仍有真实体验与可靠性缺口。当前没有正式账号云同步、自动声纹、多孩子或原生App发行闭环。

| 层 | 负责什么 | 主要位置 | 接下来需要守住的边界 |
|---|---|---|---|
| 前端 | 用户看到和操作的页面、听音/等待/失败反馈、画面、家长入口 | index.html、src/ui、src/styles | 显示真实状态，孩子界面简洁；手机和桌面共用逻辑 |
| 应用协调层 | 把输入分到聊天或绘图、维护会话与回合、取消旧工作、接收结果 | src/app.js、src/app、src/features、src/session | 谁能改哪个字段，旧结果不能覆盖新状态 |
| 后端 | 保护密钥、校验请求、调用供应商、控制身份/额度、返回结果 | server/server.mjs与模型适配文件 | 客户端不决定自己属于哪个家庭；同源不是登录或授权 |
| 模型与知识 | 听写、回应、朗读、图像；少量适龄知识上下文 | server/qwenTutor.mjs、qwenSpeech.mjs、knowledgeCardSelector.mjs等 | 模型建议必须经应用校验，不能自行宣告画好了或修改家长记录 |
| 数据层 | 保存会话、原始证据、家长修订、作品与备份 | src/data、src/services/localPersistence.js与indexedArchive.js | 证据和推测分开；保存选择、版本、删除、恢复一致 |
| 交付运维 | 自动测试、环境、发布、监测、告警、恢复、商店提交 | tests、scripts、.github/workflows及未来部署配置 | 本机能跑不等于公众可用，保留回滚与停用能力 |

“中端”在这里指应用协调和业务规则，不需要另建一个服务。不要为了分三个人就拆微服务，也不急着换React。先清楚划分既有变化边界。

一轮主要语音：设备采集与断句 → 实时ASR（必要时批量回退）→ 文字意图/安全与短答 → TTS与实际播放 → 合适时后台补充证据。画图走独立受约束操作或图片生成路径。听音、文字理解、声音合成和画面执行要分别定位失败。

## 3. 对现状的具体判断

| 工作域 | 有什么 | 仍缺什么 |
|---|---|---|
| 前端体验 | 共用导航、小宇语音入口、按需白板、成长时间筛选和家庭设置 | 真机错误恢复、听错后的纠正入口、权限/后台反馈、长内容可用性 |
| 语音 | 麦克风精确选择、实时ASR/录音回退、音量检测、TTS与连续续听 | 幼儿停顿和首字、首声等待、实际回退/音色、目标设备端到端表现 |
| 对话 | Qwen短答+后台补全、本地安全/规则回退、按年龄/身份最多3张卡 | 固定热情开场、纠正后继续猜测或追问、知识是否真正提升回答 |
| 白板 | 有限图形可操作、步骤播放、开放图片生成/编辑及审核适配 | 任意对象精确编辑不可靠，连续编辑失真；照片分享与理解未接通 |
| 档案 | 片段修订、备份恢复、损坏阻止进入、代次与部分迟到保护 | localStorage仍主存、IndexedDB是整包备用；分条事务/同代次并写/完整删除/逐次保存选择未闭合 |
| 服务与发布 | 本机Node、文件白名单、输入和异常边界、测试与CI配置 | 家庭登录、越权隔离、日额度、生产环境、远端CI证据、监控/回滚、商店流程 |

历史最近产品检查记录包括2026-10-19本机发布回归和20次文本请求；仍出现一次超时、模板化表达与纠正后追问。本轮是代码/文档抽查与计划交付，没有重跑完整产品测试、实时API、目标设备或家庭试用。示例环境的模型名和开关不代表当前实际部署配置。

现有文档也有漂移：质量说明的80%/20%与优化计划的90%/10%回归阈值不一致，QA-02要求共同确定口径；没有擅自把任一数字定成产品效果承诺。

## 4. 建议怎样分三个人

先按兴趣讨论三条主线，允许交换。每个人只主导一条，承担一条交叉复核，不要求谁包办整个前端或后端。

| 建议主线 | 包含哪些工作 | 第一份可交付结果 |
|---|---|---|
| 体验与语音 | 用户操作、设备/断句/ASR/TTS、等待与恢复 | VOICE-01：拿一轮虚构语音给出可解释阶段计时和失败位置 |
| 对话与知识质量 | 适龄回答、上下文、纠正/换题、知识卡、安全案例 | AI-01：固定10组多轮好反例，保存当前表现和评分理由 |
| 数据与工程交付 | 状态提交、档案、API权限、CI、部署与发布准备 | DATA-01：列清所有保存入口，定义临时/候选/长期及拒绝保存行为 |

上述是工作组合，不是已给同事A/B分配职责。你可以承担产品与集成，同时选择一项技术任务；技术面最广的一条可按阶段缩小，部署不应和全部数据迁移同周承诺。

每个涉及多个领域的改动，指定一名最终集成人。例如语音负责人改转写结果时，与对话负责人确认输入契约；数据负责人复核持久化影响。评测和集成是每个人完成任务的一部分。

## 5. 支持团队怎样参与

- 对象：BIZ-01需求访谈、BIZ-02成本和预算、BIZ-06付费理由。工程给实际用量与失败数据，不让他凭空猜每家庭成本。
- 园长：商业资源、同意参与的家庭触达、适龄场景反馈和合作机会。不把资源当作订单，也不自动视为临床或法律背书。
- 律师：按工程提供的真实数据流和最终渠道审查试用/儿童信息/供应商/发布/知识产权与合作安排。范围、费用和参与频次需确认，不假定已经批准。
- 三位开发者：工程实施与证据。用户承担产品取舍与协调；发布由明确批准人和执行人分别负责。

## 6. 里程碑与顺序

| 门槛 | 允许推进到哪里 | 必须有的证据 |
|---|---|---|
| G0共同上手 | 三人开始并行小任务 | 环境各自运行、容量/职责、分支审核、任务主表 |
| G1核心体验 | 准备有限成人陪同观察 | 发现/提问/纠正/换题/结束、目标设备语音、安全与保存选择的结果 |
| G2远程试用 | 指定家庭访问受控Web服务 | 身份、家庭隔离、额度、HTTPS/WSS、数据说明、恢复与法律复核 |
| G3商店发布 | 向选定商店提交 | 稳定试用结果、打包/签名/升级、主体/备案/隐私材料、渠道审核准备 |

四个门槛是验收顺序，不是四周交付承诺。G1的局部本机成人测试不必等待全部云同步/图片能力；未经验证的功能关闭。任何远程家庭访问都要先经过G2。

第一轮共同完成TEAM-01，并确认TEAM-02/03和BIZ-07的规则。之后再从VOICE-01、AI-01、DATA-01中认领，一人最多一个在做任务。首项任务如果超出可用时段，拆成“采集一轮阶段日志”“写3组纠正反例”“清点一个保存路径”等可复核子项，沿用父任务ID。

## 7. 模型怎么选、回答怎样才适合孩子

选择模型不是靠一次印象或榜单：

1. 先用同一输入分清ASR是否听错、模型是否理解错、TTS是否声音异常、应用是否回写了旧内容。
2. 固定场景与配置版本：分享、为什么、听错纠正、换题、停止、危险/医疗/隐私和画图失败。
3. 模型实验每次只改一个主要变量，例如上下文、选卡、温度或模型；保留对照和失败。
4. 人工逐轮看是否先回答、短而可理解、承认不确定、跟随纠正、不强迫提问/做任务、不虚构已经执行工具。
5. 同时报延迟、失败/回退、重复追问、话题跟随、token/音频/图片用量与成本。语音看实际可听首声，不用接口结束时间冒充。
6. 只有现有提示和上下文改法仍存在明确反复缺口，再讨论新模型或微调；当前没有自训模型计划。

还需目标设备成人验证、适龄实际观察、内容专业复核，不能把文字评测或自动安全规则视为幼儿产品验收。

## 8. 部署、客户数据和App该怎么规划

### 先受控Web，再决定原生发行

建议先评估沿用现有阿里云账户的大陆区域小规模Node部署，配域名、HTTPS/WSS和邀请访问。具体托管产品由RELEASE-01比较支持WebSocket、流式音频、成本、维护和备案条件后决定；这里没有购买、创建云资源或选择最终实例。

不需要一开始建Kubernetes。测试/正式环境和Key分开，进程可重启、健康检查、费用/故障告警、版本回退以及备份恢复要能操作。代理不能把TTS流全部缓冲完才输出。

浏览器网页、可安装PWA和原生App是不同交付。PWA不能绕过手机音频权限或锁屏限制。若做App，可先小验证Capacitor复用现有JS，或比较其他路线；当前网页需要独立构建资产目录，不能假设复制源码套壳就能通过审核。

### 数据存在哪里是产品和法律共同决定

| 数据 | 当前 | 下一步建议 |
|---|---|---|
| 家庭资料/会话/成长片段 | 本机localStorage为主，IndexedDB整包备用 | 优先可靠分条本地存储、明确保存选择和恢复；是否云同步由需求决定 |
| 原始声音 | 识别过程会发云端，应用不做长期录音档案 | 继续默认不长期保存；核对供应商实际处理/保留政策 |
| 图画与作品 | 当前状态有限保存和本地下载 | 本地独立Blob和元数据；需要云同步时用私有对象存储与授权访问 |
| 登录、家庭成员授权、调用额度 | 未正式接通 | 远程试用前放受保护的服务端；不可由前端自己认领家庭身份 |
| 运行/成本日志 | 局部状态和用量 | 最少必要的时序/版本/状态/用量，不收原话、音频、图片或姓名 |

如确有跨设备需求，再选择大陆区域托管关系型数据库与私有对象存储；Supabase目前只是草案，不能算已同步，也不默认选境外区域。“本地优先”不意味着ASR/LLM/TTS内容完全不出设备。工程整理完整数据流，由律师核对主体、区域、同意、供应商保留与删除义务。

### 中国大陆发行路线

- iOS：Apple开发者主体与签名、TestFlight测试、App Store中国区提交；核对儿童分类、家长门、隐私申报、演示账号和客服材料。审核通过不是可提前保证的事项。[Apple审核指南](https://developer.apple.com/app-store/review/guidelines/)与[儿童体验要求](https://developer.apple.com/kids/)。
- Android：按真实家庭设备先选择一个大陆商店，如华为；之后按实际需要扩展小米、OPPO、vivo、应用宝等。每渠道身份、签名、包格式、隐私和材料以当时规则为准，尚未逐渠道核实；首发中国大陆不把Google Play作为默认渠道。
- 主体与相关备案/许可：律师按最终功能确认网站/域名与APP备案、生成式AI/算法/标识、儿童数据与教育相关适用要求。不是一张通用清单全都适用，也不能因使用某家模型API就认定App自身合规。[工信部APP备案通知](https://www.gov.cn/zhengce/zhengceku/202308/content_6897341.htm?type=mobile-internet)及[生成式AI暂行办法](https://www.cac.gov.cn/2023-07/13/c_1690898327029107.htm)。
- 支付：在实际付费理由与单位成本成立后再评估，商店规则、退款与服务端权益是独立任务，不混进当前语音修复。

以上官方资料核对日期2026-10-24，仅用于安排待核对任务。具体适用与新增规则由律师在发布前检查，未形成法律结论。

## 9. 60–75分钟启动会议

| 时间 | 你可以怎么讲/做 | 当场产出 |
|---|---|---|
| 0–10分钟 | “我们先让孩子带着自己的发现来，小宇听懂、跟住；记录是后续可选价值。” | 共同核心场景与暂缓范围 |
| 10–25分钟 | 打开现有App或已有截图，演示一条路径和一条已知失败；看系统分层与基线 | 对现状达成共识，不把演示成功当全面稳定 |
| 25–40分钟 | 展开十个工作域，问各自兴趣、经验、想学什么、愿意复核什么 | 初步主线与复核组合 |
| 40–55分钟 | 确认可用时间；先TEAM-01，再一人一项候选；一起改验收条件 | 负责人、复核人、估时、下一步；能承诺才填日期 |
| 55–65分钟 | 选任务主表、PR/合并/发布规则、API预算与阻塞联络 | 明确的协作规则 |
| 65–75分钟 | 每人复述本次承诺、风险和需要谁帮助，约下次周会 | 第一条周会记录 |

开场可以说：“现在我们已经有一个能运行的原型，但离孩子愿意自然聊、家长放心用还有距离。今天我想让大家看到哪些基础已经有、哪些问题还没解决，然后按兴趣和能投入的时间，各自认领一个能验证的小问题。我们每周看实际结果和失败，再决定下一步。”

## 10. 每周怎么跟进

建议三位开发者每周固定30–40分钟，支持角色按任务或门槛参加。时段明天一起确认，不创建日程或自动提醒。

会前各自更新主表：状态、本周承诺、阻塞/下一步、证据和最后更新日期。目标日期若要改，说明原因和新范围，不用默默顺延。

周会顺序：5分钟看本轮承诺与阻塞，15分钟看演示/PR/测试或失败日志，10分钟解决跨模块与产品决定，5–10分钟选下一轮少量任务。没完成时记录卡在哪里，不按“写了很多代码”计完成。

“已验收”要求负责人完成约定范围、复核人不同于负责人、证据链接、复核结论通过和更新日期。工作簿会提示元信息是否齐全；它无法自动判断测试、代码或专业意见是否真的充分。

任务主表中“候选”只是建议讨论项；只有明确负责人和范围后改为“是”。每人同时在做最多1项，复核不超过1项。超过48小时或下一个协作时段还无法推进，先在群里写阻塞和需要的决定，不等周会。

每2–4次周会做一次产品回看：孩子主动发起与跟题有没有改善？家长是否真正需要留存？是否该缩小范围？有严重安全、丢档案、越权或费用失控问题，先停止对应路径并恢复，不等例行会议。

## 11. 表格怎样使用与移交到飞书

交付物位于仓库 `outputs/team-planning-01a02471-2026-10-24/`：离线会议看板、工作簿和行动跟踪CSV。工作簿的“项目总览”是会议入口，“行动跟踪”是日常主表，“任务验收”保留基线/范围/依赖/验收与来源。“人员与容量”“每周跟进”“决策与发布”承担不同协作记录。

优先级P0表示当前阶段的阻断项，不表示所有P0都要这周做；先筛阶段G0/G1，再讨论先后和依赖。表中后续选项不是已经承诺要做。

推荐团队选飞书多维表格为后续唯一主表：导入CSV，设置负责人/复核人、状态、阶段、本周承诺、预计小时、目标日期与证据字段；把任务验收说明关联到同一任务ID。CSV只承载值，不保留Excel公式、下拉或颜色；导入后需单独设置，不能假定完成核对会自动迁移。

也可直接共同维护Excel版，暂不导入。二者选其一；切换后另一份标只读归档。HTML是编制日规划快照，只用于会议阅读，任务后来更新不会自动回写该页面。

新增任务保留稳定ID。表内摘要支持行动跟踪第6–305行；超过预留范围要扩展摘要公式和校验范围。新增记录进入表格时检查筛选范围；不要手填汇总数字。当前62项待办是产品全景，不是冲刺容量或完成百分比。

## 12. 维护与依据
