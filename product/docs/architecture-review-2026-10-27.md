# 小宇记整体架构审查与实施记录

日期：2026-10-27。对象：`product/` 当前源码，基点 `0ba6781` 加本轮工作区修改。根目录旧模板未改动。

## 1. 判断

**作为三人团队的本机 MVP，当前架构方向合理，可以继续演进；作为面向家庭的线上、iPhone 锁屏双工产品，还没有完成必要边界。** 当前主要问题是状态归属、接口数据范围和语音生命周期，不是缺少框架。

推荐保留原生 JavaScript 前端、Node 模块化单体后端与现有安全/知识/白板模块。下一阶段增加一个独立 Node LiveKit Agent 进程；业务规则仍共享，媒体调度由 Agent 负责。不同时引入 React 重写、Python 业务副本、微服务网关、消息队列或向量库。三人的实际工时尚未承诺，按验收门槛推进。

中国大陆家庭、iPhone 优先已确认；产品先验证 3–6 岁直接语音，0–3 岁家长辅助。仍保持自由开始/结束，不默认增加陪伴倒计时。

## 2. 分层审查

| 层 | 现状与判断 | 合理的职责 | 需要继续改的部分 |
|---|---|---|---|
| 前端视图 | 四个视图、共享导航、白板与样式已模块化，适合继续使用 | 呈现设备状态、孩子交互、家长操作；执行受限白板命令 | `app.js` 仍约 1,700 行，兼管事件、语音、绘图、存储；render 会读档案库 |
| 中间业务层 | 已有 conversationController、conversationCommit、drawingState、安全规则；方向正确 | 话轮身份、会话有效性、业务决策、受限结果提交与取消 | pending 仍提交完整候选状态；存储与渲染绑定；生成回答和实际听到的回答尚未区分 |
| 后端 API | Node 同源服务与模型适配器足够支撑本机验证 | 请求校验、服务端密钥、供应商适配、取消、超时、结构校验 | 同源检查不等于家庭身份认证；缺家庭隔离、按家庭配额、生产部署与观测 |
| 数据层 | localStorage 主存储、IndexedDB 整包备用、修订/代次保护已有价值 | 家长可查看、编辑、下载、删除；拒绝迟到结果覆盖 | 不是跨标签页原子事务；频繁保存整包；不是云同步；全部派生数据删除仍有缺口 |
| 实时语音 | 单句实时 ASR + 文本 quick/complete + PCM 流式播报 | 保留为功能基线和故障回退 | 当前回答时停止听入；非 token 流式；隐藏页面暂停；没有自动全双工和原生锁屏 |
| 内容与知识 | 适龄规则、有限知识卡、输出校验、白板约束可复用 | 跟随孩子的问题、约束能力声明、证据与推测分离 | 有限关键词规则不是完整语义安全或事实校验；模型质量需独立评测 |

“中端”在这里指应用编排和共享业务模块，不需要另建一个中台服务。目前这些模块分布在浏览器与 Node 中；目标是明确谁负责决策、谁负责提交，而不是追求所有逻辑只存在于一个进程。

## 3. 本轮已改的运行代码

### 3.1 对话接口从整份状态改成有限上下文

新增 `src/services/tutorContext.js`，由前端 `llmClient.js` 和后端 `server.mjs` 共用。前端在发出请求前筛选，服务端再筛选一次，旧客户端直接传整份状态也不会被作为业务上下文使用或整体回传。服务器仍可能接收到旧客户端发送的原始请求体；这一兼容处理不代表旧客户端已经停止上传。

两个文本 Tutor 接口仅接受这些上下文：

| 字段 | 范围 |
|---|---|
| profile | 昵称、年龄段、兴趣、目标；字符串有长度限制 |
| activeSpeaker | 当前称呼与角色；不含家庭成员表、身份 ID 或声纹登记 |
| messages | 最近最多 12 条通过现有安全过滤的 child/tutor 文字；每条最多 4,000 字符，只保留角色、文字、说话人称呼/角色 |
| memory | 最多 6 个兴趣、4 条近期观察；不发送完整 Student Model 或作品 |
| activeLesson | 仅活动类型及是否等待回答；quick 用它保留已有本地判题分路 |
| safetyContext | 短暂保护类别、剩余轮次、失效时间，不包含披露原文 |
| board | 固定 blank；图形操作仍走既有独立绘图接口 |

排除家长 PIN 哈希、consent 等设置、家庭成员表、会话摘要、完整孩子档案、作品、图片 base64 和界面状态。有限上下文仍包含昵称和近期文字，不能称为匿名数据，也不能代替身份验证或数据政策。

`POST /api/tutor/quick` 仍返回短答与运行状态。`POST /api/tutor` 定位为后台提取，返回 `memory`（仅兴趣/近期观察）、`growthEvidence`、`llmStatus`；不回传 profile、messages、board、studentModel 或替换应用状态。后端提取不重复判题；前端将这两个 memory 字段合入请求时的本地 memory，再经过原有并发基线/commit 校验。掌握度、会话数等本地字段不从服务端重建。

这是现有 HTTP 路径的合同收紧。LiveKit 的 room/session/generation/archiveEpoch 合同尚未实现，不能把这里的 `state` 字段当作已完成的实时会话协议。需要部署时前后端一起发布，避免旧页面依赖完整返回值；旧绘图、ASR、TTS 路由未改变。

### 3.2 业务计算不再直接访问档案适配器

`tutorEngine.js` 移除对 `localStudentDb.js` 的导入；计算练习、答案或故事选择时只返回候选结果，并通过可选 `onStudentEvent` 收集事件。app 在本地发布路径或 quick commit 接受后，利用已有存储边界保存模型与事件。服务端调用默认不收集事件，不再写入 Node 进程共用的 `memoryDb`。

保留既有事件类型与练习行为；没有删除旧资料或改变持久化格式。这里保证的是业务函数不直接读写档案库，**不宣称所有函数已严格纯化**：时间/随机计划仍存在；app 的 pending 状态仍包含候选数据，整包保存与多次档案写入也尚未变成一个原子事务。

### 3.3 明确区分取消与故障回退

`qwenTutor.mjs` 在入口、模型结果返回后和异常处理处检查调用者的 AbortSignal。调用已取消时抛出取消结果，不再返回本地回答；普通网络失败和供应商超时仍保留既有回退。

新增测试覆盖调用前取消、处理中取消，以及适配器忽略取消后仍返回结果。原有上游取消/超时测试同步要求取消必须拒绝。这是 LiveKit 可中断链路的基础，不等于音频队列清空、设备尾音或已播前缀已经实现。

## 4. LiveKit 在这个架构中的位置

| 模块 | 负责什么 | 不应承担什么 |
|---|---|---|
| Web / iPhone 客户端 | 房间连接、麦克风/扬声器、播放反馈、家长停止、显示/保存受限事件 | 再独立启动一套 LLM/TTS；把全文备份放入 room metadata |
| 现有 Node API 的会话入口（待实现） | 家庭/设备授权、短期房间凭证、会话生命周期、费用边界 | 逐帧中转所有音频；把本机家长码当网络鉴权 |
| Node LiveKit Agent（待实现） | 连续媒体输入、断句、打断、generation 取消、输出队列、已播结果 | 直接修改浏览器 localStorage；决定成长内容一定要保存 |
| 小宇共享业务模块 | 安全/告别、适龄回应、知识卡、受限绘图、成长证据候选 | 操作 DOM、持有播放器、直接保存家庭档案 |
| ASR / LLM / TTS 适配器 | 规范化增量结果、终结/取消/错误语义、供应商耗时 | 绕过安全判断或自己增加第二个话轮裁决者 |
| 档案接收层 | 校验会话/记录修订/清空代次与保存策略，提交有限结果 | 将未播放完整回答视作孩子已经听到；让后台结果复活已删除资料 |

一段音频同时能收发是媒体能力；系统识别插话并取消生成是系统级双工行为；模型自身持续联合理解/生成音频是另一层能力。当前文本 ASR 链路不保留完整语气信息，不能因为接了 LiveKit 就声称理解了儿童情绪或达到了模型级原生 full-duplex。

先保持模型基线，验证传输与取消；再单独替换 ASR、中文 LLM 和 TTS。Lychee-FD 继续用作研究对照，不拆它的内部模型作为现有业务模块。4070 Super 12GB 留给离线评测或有明确收益的本地候选实验，不作为线上主链路的依赖。

具体接口、指标、iPhone 锁屏分支与分阶段计划见 [LiveKit 迁移设计](livekit-hybrid-architecture.md)。当前尚未安装或运行 LiveKit。

## 5. 三人接下来的实施顺序

以下是估算的人日，不是已承诺的日历日期。每个人先认领一个主方向，交叉复核边界；不同时开启多个架构迁移。

| 顺序 | 任务与负责人建议 | 估算 | 验收与依赖 |
|---|---|---:|---|
| A | 应用负责人：收敛当前语音生命周期，定位续听偶发超时；补 pending 与已发布状态边界 | 2–4 人日 | 快慢 quick/complete、播放失败、手动停止、隐藏页面和迟到回调可控复现；停止后不自动续听 |
| B | 后端负责人：做会话授权/房间凭证实验，限定开发设备与单会话；远程家庭前补真实账户隔离 | 3–5 人日 | 过期/越权/重复启动/结束后请求均拒绝；密钥不进客户端；不开放无鉴权公网模型代理 |
| C | 语音负责人：独立 Node Agent + 当前 ASR/TTS 基线，业务共享模块薄封装 | 4–6 人日 | 持续听入、插话取消全链路、旧 generation 不发布；与旧路径能切换且不双开麦克风/播放器 |
| D | 应用与语音负责人：生成/已播/打断状态及事件归约；原生 iPhone 锁屏实验 | 4–7 人日 | 未播后半句不进入“已听到”历史；30 分钟锁屏、来电、蓝牙、网络切换、前台恢复真机记录 |
| E | 后端与应用负责人：耐久存储、删除与恢复语义补齐，再考虑云同步 | 4–7 人日 | 同代次跨标签页冲突、清空派生数据、后台迟到结果、迁移失败均有回归；不要直接上线 Supabase 草案 |

数据改造不必阻塞一次隔离的语音实验，但必须阻止未验收的后台证据写入真实家庭档案。iPhone 媒体实验可在 A–C 期间先做可行性验证，不先重写全部家长页面。

本轮没有新增依赖、云资源或付费调用。各阶段预算仍沿用研究计划的计算方式，正式开通前核对地区/权限/实际用量；不根据 mock 测试推算真实延迟或每小时成本。
